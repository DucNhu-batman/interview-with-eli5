Là gì

Bán lẻ một mẩu ứng dụng

Widget (tiện ích nhúng) là một mẩu giao diện chạy được bên trong trang của người khác — hộp chat, ô tra cứu, nút đặt lịch. Cách làm trong Angular là gói component thành custom element (phần tử tuỳ chỉnh, chuẩn Web Components) rồi phát hành một file script duy nhất.

// main.ts của bản widget
const app = await createApplication({ providers: [provideHttpClient()] });
const el = createCustomElement(TraCuuWidget, { injector: app.injector });
customElements.define('qp45-tra-cuu', el);

// Trang khách chỉ cần hai dòng
<script src="https://cdn.noi-bo/tra-cuu.js" defer></script>
<qp45-tra-cuu ma-kho="KHO-0001"></qp45-tra-cuu>

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Dùng lại được ở mọi nơi: trang WordPress, portal cũ, ứng dụng của đối tác.
  • Một nguồn code duy nhất cho cả ứng dụng chính lẫn widget.
  • Tích hợp cực nhẹ cho bên nhúng: chỉ một thẻ script và một thẻ HTML.
  • Nâng cấp tập trung: sửa ở nguồn là mọi trang nhúng đều được bản mới.

Ví dụ mặt lợi

// Cùng một component, hai nơi dùng
<qp45-tra-cuu [maKho]="ma()" />         // trong app Angular
<qp45-tra-cuu ma-kho="KHO-0001">       // trong trang HTML thuần
// Sửa nghiệp vụ một lần, cả hai nơi cùng cập nhật

−Mặt hại

  • Nặng. Widget mang theo cả runtime Angular — hàng trăm KB cho một ô tra cứu.
  • Xung đột CSS hai chiều nếu không dùng Shadow DOM để cách ly.
  • Chỉ nhận chuỗi qua thuộc tính HTML, muốn truyền object phải gán bằng JavaScript.
  • Vấn đề CORS và bảo mật: mọi API phải mở đúng nguồn gốc, và token không được lộ.
  • Hai widget trên cùng trang có thể tranh nhau đăng ký cùng một tên phần tử.

Ví dụ mặt hại

<qp45-tra-cuu bo-loc="{ tuNgay: '2026-01-01' }">
// → nhận được CHUỖI, không phải object
document.querySelector('qp45-tra-cuu').boLoc = { tuNgay: … };  // ✓

customElements.define('qp45-tra-cuu', el);
// nhúng script hai lần → DOMException: name has already been used

Từ điển

Thuật ngữ đã dùng

Thuật ngữNghĩa tiếng Việt
widgetTiện ích nhúng được vào trang khác.
custom elementPhần tử HTML tuỳ chỉnh theo chuẩn Web Components.
Shadow DOMCây DOM riêng, cách ly style với trang chủ.
CORSCơ chế cho phép trang này gọi API của tên miền khác.
CDNMạng phân phối nội dung, nơi đặt file script công khai.
