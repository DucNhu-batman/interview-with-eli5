Là gì

Người soát vé lúc biên dịch

TypeScript thêm một lớp kiểm tra trước khi chạy: bạn dán nhãn cho biến, tham số, kết quả trả về; trình biên dịch đối chiếu và báo lỗi nếu lệch. Khi build xong, toàn bộ nhãn bị xoá — trình duyệt chỉ nhận JavaScript thuần.

let ten: string = 'An';
let tuoi: number | null = null;          // union — một trong các kiểu
const ds: string[] = ['a', 'b'];
const cap: [number, string] = [1, 'a'];    // tuple — bộ có thứ tự

interface SanPham { id: number; ten: string; gia?: number; }
type TrangThai = 'moi' | 'dang_xu_ly' | 'xong';   // literal union

enum Vai { Admin = 'ADMIN', User = 'USER' }

function tinh(a: number, b = 1): number { return a + b; }

Ba kiểu đặc biệt phải phân biệt: any tắt hẳn kiểm tra (nên tránh); unknown cũng chứa được mọi thứ nhưng bắt bạn kiểm tra trước khi dùng (an toàn); never nghĩa là "không bao giờ có giá trị", dùng để bảo đảm đã xử lý hết mọi nhánh.

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Bắt lỗi sớm. Gõ sai tên thuộc tính, thiếu tham số, sai kiểu — biết ngay khi gõ.
  • Gợi ý code thông minh. Editor biết object có gì, đỡ phải mở tài liệu.
  • Refactor an toàn. Đổi tên một trường, trình biên dịch chỉ ra mọi chỗ phải sửa.
  • Kiểu là tài liệu sống. interface mô tả dữ liệu chính xác hơn mọi comment.

Ví dụ mặt lợi

interface Kho { id: number; ten: string; }
function hien(k: Kho) { return k.tenKho; }
// ✗ Báo ngay khi gõ: Property 'tenKho' does not exist on type 'Kho'.
// Đổi tên trường trong interface → editor chỉ ra đủ 40 chỗ phải sửa

−Mặt hại

  • Không bảo vệ lúc chạy. Dữ liệu API trả về sai kiểu vẫn lọt — nhãn đã bị xoá khi build.
  • Tốn thời gian viết kiểu, nhất là với dữ liệu lồng nhau nhiều tầng.
  • Lỗi kiểu đôi khi rất dài dòng, người mới đọc không ra vấn đề nằm ở đâu.
  • any lây lan. Một chỗ buông là mất an toàn cả một nhánh code.

Ví dụ mặt hại

const kho = await firstValueFrom(http.get<Kho>('/api/kho/1'));
// Máy chủ đổi "ten" thành "tenKho" mà không báo:
kho.ten.toUpperCase();   // ✗ TypeError lúc chạy — nhãn kiểu đã bị xoá khi build

const dl: any = phanHoi;
dl.abc.xyz();            // ✗ any lây: từ đây trở đi không còn kiểm tra gì nữa

Từ điển

Thuật ngữ đã dùng

Thuật ngữNghĩa tiếng Việt
type annotationNhãn kiểu — khai kiểu cho biến/tham số.
interfaceBản mô tả hình dạng của một object.
union typeKiểu hợp — giá trị thuộc một trong nhiều kiểu.
tupleBộ có số phần tử và kiểu cố định theo thứ tự.
enumTập hằng số có tên.
any / unknown / neverTắt kiểm tra / chưa biết kiểu / không thể có giá trị.
compile timeLúc biên dịch, trước khi chương trình chạy.
