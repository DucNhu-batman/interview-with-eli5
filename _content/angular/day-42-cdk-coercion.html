Ép kiểu ở cổng vào

Trong template, <my-input disabled> truyền vào chuỗi rỗng, còn disabled="false" truyền vào chuỗi "false" — cả hai đều là truthy (giá trị được coi là đúng). Nếu component chỉ viết if (this.disabled) thì cả hai đều bị khoá, trái ý người dùng.

Coercion (ép kiểu) chuẩn hoá đầu vào ngay tại cổng. Angular hiện đại làm việc này bằng transform của input():

export class ONhap {
  disabled = input(false, { transform: booleanAttribute });
  soDong  = input(3, { transform: numberAttribute });
}

// dùng ở ngoài — cách nào cũng cho kết quả đúng
<qp45-o-nhap disabled />                <!-- true -->
<qp45-o-nhap disabled="false" />        <!-- false -->
<qp45-o-nhap [disabled]="dangKhoa()" /> <!-- theo biến -->

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Component cư xử như thẻ HTML chuẩn, người dùng không phải nhớ luật riêng.
  • Logic bên trong sạch: đã chắc chắn là boolean/number, không phải kiểm tra kiểu.
  • Ép kiểu tập trung một chỗ, không rải Number(...) khắp nơi.
  • Viết được transform riêng cho trường hợp đặc thù (chuỗi ngày → Date).

Ví dụ mặt lợi

// Không có coercion:
<qp45-o-nhap disabled="false" />   // → vẫn bị khoá (sai)

// Có booleanAttribute:
<qp45-o-nhap disabled="false" />   // → false, đúng ý người dùng
<qp45-o-nhap disabled />           // → true

−Mặt hại

  • Che giấu lỗi kiểu. Truyền nhầm một chuỗi rác vẫn được ép thành giá trị nào đó thay vì báo lỗi.
  • Kiểu vào và kiểu ra khác nhau nên đọc code phải để ý mới biết bên trong nhận gì.
  • Transform tự viết dễ nuốt lỗi nếu quên xử lý null/NaN.
  • Thêm một khái niệm nữa cho người mới, dù chỉ để giải quyết một đặc thù của HTML.

Ví dụ mặt hại

soDong = input(3, { transform: numberAttribute });
<qp45-o-nhap soDong="ba" />   // → NaN, không có cảnh báo nào

// Transform tự viết quên chặn NaN:
transform: (v: unknown) => Number(v)      // ✗
transform: (v: unknown) => Number(v) || 0 // ✓ an toàn hơn
