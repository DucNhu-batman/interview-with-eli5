Validator biết chờ

Async validator (kiểm tra bất đồng bộ) trả về một Observable/Promise thay vì kết quả tức thì. Trong lúc chờ, control mang trạng thái PENDING (đang chờ) — dùng nó để hiện vòng xoay nhỏ và khoá nút Lưu.

export function maChuaTonTai(api: KhoService): AsyncValidatorFn {
  return (c: AbstractControl) =>
    timer(400).pipe(                        // chống dội: chờ người dùng ngừng gõ
      switchMap(() => api.kiemTraMa(c.value)),
      map((daTonTai) => (daTonTai ? { maTrung: true } : null)),
      catchError(() => of(null)),          // lỗi mạng thì đừng chặn người dùng
      first(),                              // BẮT BUỘC: phải complete
    );
}

ma: ['', [Validators.required], [maChuaTonTai(this.api)]],   // mảng thứ 3

Ba luật sống còn: (1) async validator chỉ chạy khi các validator đồng bộ đã hợp lệ; (2) luồng trả về phải kết thúc, nếu không control kẹt ở PENDING mãi mãi; (3) luôn chống dội trước khi gọi API.

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Báo trùng ngay khi gõ, người dùng không phải bấm Lưu mới biết mình sai.
  • Nằm trong hệ thống form nên trạng thái hợp lệ của cả form tự tính đúng.
  • Trạng thái PENDING có sẵn để hiện chỉ báo đang kiểm tra.
  • Dùng lại được cho cả màn tạo mới lẫn màn sửa, chỉ cần đổi tham số loại trừ id hiện tại.

Ví dụ mặt lợi

@if (form.controls.ma.pending) { <span class="spin">Đang kiểm tra…</span> }
@if (form.controls.ma.errors?.['maTrung']) {
  <small>Mã kho đã tồn tại trên hệ thống</small>
}
<button [disabled]="form.invalid || form.pending">Lưu</button>

−Mặt hại

  • Luồng không complete là treo form. Control mắc kẹt PENDING, nút Lưu không bao giờ bật lại.
  • Bắn API mỗi lần gõ nếu quên chống dội — máy chủ lãnh đủ.
  • Không thay được kiểm tra ở máy chủ. Hai người gõ cùng lúc vẫn có thể trùng.
  • Test khó hơn, phải giả lập cả thời gian lẫn phản hồi mạng.

Ví dụ mặt hại

// Thiếu first()/take(1): luồng không bao giờ complete
return api.kiemTraMa(c.value).pipe(map(…));
// → form.pending mãi là true → nút Lưu vô hiệu vĩnh viễn

// Thiếu timer/debounce: gõ "KHO-0001" = 8 request

Trong dự án này, lỗi trùng do backend trả về (409 / errorCode: "CONFLICT") vẫn phải hiện inline dưới ô nhập bằng đúng câu backend gửi lên — async validator chỉ là lớp báo sớm cho dễ chịu, không thay thế được lớp kiểm tra cuối ở máy chủ.

Từ điển

Thuật ngữ đã dùng

Thuật ngữNghĩa tiếng Việt
async validatorKiểm tra hợp lệ bất đồng bộ (thường hỏi máy chủ).
PENDINGTrạng thái đang chờ kết quả kiểm tra.
debounceChống dội — chờ ngừng gõ mới gọi.
completeLuồng kết thúc; điều kiện bắt buộc của async validator.
race conditionĐua — hai người cùng tạo một mã trong cùng thời điểm.
