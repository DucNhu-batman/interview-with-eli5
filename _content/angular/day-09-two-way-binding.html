Là gì

Đường tắt của hai thứ có sẵn

Angular quy ước: nếu component có một input tên x và một output tên xChange, thì [(x)]="bien" tự động được dịch thành:

<app-con [x]="bien" (xChange)="bien = $event" />

Chỉ vậy thôi. [(ngModel)] cũng chạy đúng luật đó (ngModel + ngModelChange).

// Cách mới nhất — model() lo cả hai đầu
export class ONhapSo {
  gia = model(0);                       // vừa là input, vừa phát giaChange
  tang() { this.gia.update((v) => v + 1); }
}

// Cách viết tay tương đương
export class ONhapSo {
  gia = input(0);
  giaChange = output<number>();
  tang() { this.giaChange.emit(this.gia() + 1); }
}

// Dùng ở cha
<app-o-nhap-so [(gia)]="soLuong" />

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Template ngắn gọn. Một dòng thay cho hai, ý định rõ ràng: "ô này gắn với biến kia".
  • Chuẩn hoá. Ai đọc cũng hiểu ngay, không phải tự đặt tên sự kiện mỗi nơi một kiểu.
  • model() gọn nhất. Con đọc/ghi như một signal bình thường, Angular tự phát sự kiện.
  • Hợp cho component ô nhập dùng lại nhiều nơi (chọn ngày, nhập tiền, chọn nhiều mục).

Ví dụ mặt lợi

// Component ô nhập số dùng lại khắp nơi, một dòng là xong
<qp45-o-nhap-so [(gia)]="soLuong" />
<qp45-o-nhap-so [(gia)]="tonKhoToiThieu" />

// Bên trong chỉ cần: gia = model(0); gia.update((v) => v + 1);

−Mặt hại

  • Che mất luồng dữ liệu. Nhìn [(x)] không thấy rõ ai là người thay đổi giá trị — khó lần khi có bug.
  • Dễ tạo vòng lặp cập nhật. Con phát sự kiện trong lúc đang nhận giá trị mới có thể gây ExpressionChangedAfterItHasBeenChecked.
  • Không có chỗ chặn/validate. Cần kiểm tra trước khi nhận giá trị thì phải tách lại thành input + output riêng.
  • Trái với luồng một chiều. Dùng tràn lan làm state bị phân tán, khó đưa lên một nơi quản lý tập trung.

Ví dụ mặt hại

<qp45-o-nhap-so [(gia)]="soLuong" />
// ✗ muốn chặn giá trị âm trước khi nhận thì không có chỗ nào để chặn
// phải tách lại thành:
<qp45-o-nhap-so [gia]="soLuong()" (giaChange)="datGia($event)" />

datGia(v: number) { if (v >= 0) this.soLuong.set(v); }

Nên dùng khi: component là một "ô nhập" đúng nghĩa, giá trị đơn giản, không cần xử lý gì thêm. Nên tách hai chiều thành input/output riêng khi: thay đổi cần được kiểm tra, ghi log, hoặc phải đi qua một facade.
