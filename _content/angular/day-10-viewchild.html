Là gì

Đặt tên cho một phần tử rồi cầm lấy nó

Template variable (biến template) là cái nhãn #ten gắn vào một phần tử. Trong template, dùng nhãn đó là gọi được luôn:

<input #oTim (keyup.enter)="tim(oTim.value)" />
<button (click)="oTim.focus()">Tìm</button>

Còn khi cần dùng từ lớp TypeScript, phải khai một view query (truy vấn view):

export class ManTimKiem {
  oTim = viewChild<ElementRef<HTMLInputElement>>('oTim');
  cacDong = viewChildren(DongKetQua);
  bang = viewChild.required(IamTable);

  focus() { this.oTim()?.nativeElement.focus(); }
}

Quy ước của dự án này: code mới không dùng decorator @ViewChild/@ViewChildren nữa mà dùng signal query viewChild()/viewChildren(). Signal query không có tuỳ chọn { static: true }: nó chỉ có giá trị sau khi view được dựng, nên mọi thiết lập từng đặt trong ngOnInit phải chuyển sang effect(), hoặc tốt hơn là để component con tự đẩy ra bằng output().

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Làm được việc mà binding không làm nổi: focus, cuộn tới, đo kích thước, gọi method của thư viện bên thứ ba.
  • Điều khiển component con trực tiếp (mở dialog, reset bảng) mà không phải bịa thêm input.
  • Signal query gọn hơn decorator: kiểu chặt hơn, đọc như mọi signal khác, tự cập nhật khi view đổi.
  • viewChild.required khẳng định luôn có, khỏi phải kiểm tra undefined.

Ví dụ mặt lợi

// Việc mà data binding không làm được
oTim = viewChild<ElementRef<HTMLInputElement>>('oTim');

moDialog() {
  this.oTim()?.nativeElement.focus();       // đưa con trỏ vào ô tìm
  this.bang().scrollToIndex(0);             // cuộn bảng về đầu
}

−Mặt hại

  • Gắn chặt cha vào con. Cha biết quá nhiều về cấu tạo con, đổi con là gãy cha.
  • Rỗng khi phần tử nằm trong @if hoặc chưa được vẽ — quên kiểm tra là lỗi lúc chạy.
  • Chưa sẵn sàng trong ngOnInit, dễ khiến người quen decorator viết sai chỗ.
  • Sờ thẳng vào DOM giảm tính di động (SSR, môi trường không có document) và khó test hơn.

Ví dụ mặt hại

ngOnInit() {
  this.oTim()?.nativeElement.focus();   // ✗ luôn undefined
}                                       // view chưa dựng xong ở thời điểm này

// chữa:
constructor() { effect(() => this.oTim()?.nativeElement.focus()); }

// Và cha gắn quá chặt vào con:
this.bang().internalReset();   // đổi tên method trong IamTable → cha gãy

Thứ tự ưu tiên: input/output trước → template variable trong template → view query chỉ khi thật sự cần cầm tay chỉ việc.

Từ điển

Thuật ngữ đã dùng

Thuật ngữNghĩa tiếng Việt
template variableBiến template — nhãn #ten trỏ tới phần tử/component.
view queryTruy vấn view — lấy phần tử trong template của chính component.
ElementRefVỏ bọc quanh phần tử DOM thật.
signal queryTruy vấn trả về signal (viewChild(), viewChildren()).
effect()Hàm chạy lại mỗi khi signal nó đọc thay đổi.
SSRKết xuất phía máy chủ — nơi không có window/document.
