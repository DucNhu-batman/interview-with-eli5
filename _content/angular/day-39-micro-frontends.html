Là gì

Nhiều ứng dụng, một màn hình

Micro frontend (giao diện siêu nhỏ) là cách áp mô hình microservice lên phía trình duyệt: mỗi khu vực nghiệp vụ là một ứng dụng riêng, build riêng, phát hành riêng; một ứng dụng "vỏ" (shell/host) ghép chúng lại lúc chạy. Cách phổ biến nhất là Module Federation của Webpack.

// shell — nạp một màn hình từ ứng dụng khác lúc chạy
{
  path: 'kho',
  loadChildren: () => loadRemoteModule({
    remoteEntry: 'https://kho.noi-bo/remoteEntry.js',
    exposedModule: './Routes',
  }).then((m) => m.KHO_ROUTES),
}

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Phát hành độc lập. Đội A lên bản mới không phải chờ đội B.
  • Ranh giới rõ ràng giữa các miền nghiệp vụ, giảm giẫm chân nhau.
  • Nâng cấp dần được: phần cũ giữ nguyên, phần mới viết bằng công nghệ mới.
  • Build nhanh hơn vì mỗi ứng dụng nhỏ đi nhiều.

Ví dụ mặt lợi

// Đội Kho sửa lỗi lúc 10h, deploy lúc 10h30
// Shell không build lại, đội Báo cáo không bị ảnh hưởng
// Người dùng tải lại trang là thấy bản mới của riêng khu vực Kho

−Mặt hại

  • Hạ tầng phức tạp hẳn lên: nhiều pipeline, nhiều tên miền, nhiều nơi để hỏng.
  • Lệch phiên bản thư viện. Hai ứng dụng dùng hai bản Angular khác nhau là nguồn lỗi rất khó chẩn đoán.
  • Tải nặng hơn nếu không chia sẻ được thư viện chung.
  • Giao diện dễ thiếu nhất quán khi mỗi đội tự làm component riêng.
  • Gỡ lỗi xuyên ứng dụng rất mệt, stack trace đi qua nhiều gói từ nhiều nguồn.

Ví dụ mặt hại

// Shell dùng Angular 18, remote build bằng Angular 17
// → NG0203: inject() must be called from an injection context
// Lỗi chỉ xuất hiện trên môi trường thật, sau khi deploy riêng lẻ

shared: { '@angular/core': { singleton: true, strictVersion: true } }
// ↑ khai thiếu dòng này là mỗi remote nạp một bản Angular riêng

Khi nào nên dùng: nhiều đội độc lập, nhiều nhịp phát hành khác nhau, ứng dụng đủ lớn để chia. Một sản phẩm do một đội làm thì lazy loading theo feature đã đủ — micro frontend chỉ thêm chi phí.

Từ điển

Thuật ngữ đã dùng

Thuật ngữNghĩa tiếng Việt
micro frontendChia giao diện thành nhiều ứng dụng độc lập.
shell / hostỨng dụng vỏ, chịu trách nhiệm ghép các phần lại.
remoteỨng dụng con được vỏ nạp vào lúc chạy.
Module FederationCơ chế của Webpack cho phép chia sẻ mô-đun giữa các bản build.
singleton (thư viện)Chỉ nạp một bản duy nhất của thư viện dùng chung.
