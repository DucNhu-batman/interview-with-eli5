Bốn kiểu công thức

Provider không nhất thiết là "tạo một object từ class". Có bốn dạng, mỗi dạng giải một bài toán:

DạngÝ nghĩaDùng khi
useClassTạo bằng class nàyThay bản thật bằng bản giả/bản khác
useValueTrả về đúng giá trị nàyCấu hình, hằng số, đối tượng có sẵn
useFactoryGọi hàm để tạoCần rẽ nhánh theo môi trường hoặc dữ liệu
useExistingDùng lại bản của token khácĐặt bí danh cho một service đã có
 
// Token cho thứ không phải class (chuỗi, object cấu hình)
export const API_URL = new InjectionToken<string>('API_URL');

bootstrapApplication(App, {
  providers: [
    { provide: API_URL, useValue: 'https://api.example.com' },
    { provide: LogService, useClass: environment.production ? LogRong : LogDayDu },
    { provide: CacheService, useFactory: () => new CacheService(inject(API_URL)) },
  ],
});

Cơ chế

Cây injector — ai gần hơn thì thắng

Injector xếp thành cây: gốc ứng dụng → route → component → directive. Khi một component hỏi một token, Angular tìm từ injector gần nhất đi ngược lên. Ai khai gần hơn thì bản đó được dùng.

Nhờ vậy có thể khai một service riêng cho một nhánh route (mỗi lần vào màn là một bản mới, thoát màn là bị huỷ) — đúng mô hình facade theo màn hình mà dự án đang dùng.

Bẫy hay gặp: khai cùng một service ở cả root và providers của component sẽ tạo ra hai bản khác nhau. Hai nơi tưởng dùng chung state hoá ra mỗi nơi một kho — bug rất khó nhìn ra.

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Cấu hình theo môi trường mà không rải if (production) khắp code.
  • Vòng đời đúng nhu cầu. State theo màn hình sống và chết cùng màn hình đó.
  • Token cho mọi thứ, kể cả chuỗi và object thuần — vẫn giữ được kiểm tra kiểu.
  • Thay thế hiện thực cho test hoặc cho một khách hàng riêng mà không sửa code dùng.

Ví dụ mặt lợi

// Đổi hiện thực theo môi trường, code dùng không đổi một dòng
{ provide: LogService, useClass: environment.production ? LogRong : LogDayDu }

// Và state sống đúng bằng vòng đời màn hình:
{ path: 'kho', providers: [KhoStore], children: [...] }
// rời khỏi /kho → KhoStore bị huỷ, không còn dữ liệu thừa

−Mặt hại

  • Cây injector khó hình dung. Không có gì hiển thị bản nào đang được dùng, phải suy luận.
  • Nhân bản ngoài ý muốn khi khai provider ở nhiều tầng.
  • useFactory dễ bị lạm dụng thành nơi nhét logic khởi tạo phức tạp.
  • Nhiều khái niệm cho một việc đơn giản — người mới thấy nặng nề so với việc chỉ new một object.

Ví dụ mặt hại

@Injectable({ providedIn: 'root' }) class GioHangStore {}

@Component({ providers: [GioHangStore] })   // ✗ khai lại lần nữa
class ManGioHang {}
// → Header đọc bản ở root, màn giỏ hàng ghi vào bản riêng của nó
// → thêm sản phẩm mà số trên header không nhúc nhích. Không lỗi nào được ném.

Thuật ngữNghĩa tiếng Việt
InjectionTokenToken tự tạo cho giá trị không phải class.
useClass / useValueTạo bằng class chỉ định / trả về giá trị có sẵn.
useFactoryGọi một hàm để tạo phụ thuộc.
injector treeCây bộ tiêm phân tầng theo cấu trúc ứng dụng.
scopePhạm vi sống của một bản service.
environmentFile cấu hình theo môi trường (dev/prod).
