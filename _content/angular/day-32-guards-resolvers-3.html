Là gì

Dọn cỗ xong mới mời khách vào

Resolver (bộ giải dữ liệu) là hàm chạy trước khi component được tạo. Router chờ nó xong rồi mới điều hướng, và đặt kết quả vào route.data. Component nhận dữ liệu đã sẵn sàng, khỏi phải xử lý trạng thái "đang tải".

export const khoResolver: ResolveFn<Kho> = (route) =>
  inject(KhoService).chiTiet(route.paramMap.get('id')!);

{ path: 'kho/:id', component: ChiTietKhoComponent, resolve: { kho: khoResolver } }

// Trong component — cách gọn nhất
{ path: 'kho/:id', component: ChiTietKhoComponent,
  resolve: { kho: khoResolver }, data: { }, }
readonly kho = toSignal(inject(ActivatedRoute).data.pipe(map((d) => d['kho'] as Kho)));

// Hoặc bật withComponentInputBinding() rồi nhận thẳng qua input cùng tên
kho = input.required<Kho>();

Mẹo hiện đại: bật provideRouter(routes, withComponentInputBinding()) thì mọi tham số route và dữ liệu resolver tự chảy vào input() cùng tên. Component không cần biết ActivatedRoute là gì — dễ test hơn hẳn.

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Component sạch: không có trạng thái tải, không có dữ liệu undefined ở lần vẽ đầu.
  • Không nhấp nháy khung rỗng rồi mới đổ dữ liệu.
  • Bắt lỗi sớm: id không tồn tại thì chuyển hướng ngay, không vẽ màn lỗi.
  • Tải song song nhiều nguồn trước khi vào, dùng chung một chỗ khai báo.

Ví dụ mặt lợi

{ path: ':id', component: ChiTietKho, resolve: { kho: khoResolver } }

export class ChiTietKho { kho = input.required<Kho>(); }
// Không có trạng thái "đang tải", không có kho() === undefined,
// không nhấp nháy khung rỗng. Id sai → chuyển hướng trước khi vẽ.

−Mặt hại

  • Ứng dụng như treo. Màn cũ vẫn hiện, chưa có gì báo là đang tải — phải tự bật chỉ báo từ sự kiện router.
  • Chậm nhất quyết định tất cả. Một API chậm giữ chân toàn bộ màn hình.
  • Khó hiện lỗi tử tế. Lỗi xảy ra khi chưa có màn hình nào để hiển thị nó.
  • Dữ liệu không tự làm mới khi ở lại màn lâu — resolver chỉ chạy lúc vào.

Ví dụ mặt hại

resolve: { kho: khoResolver, lichSu: lichSuResolver }
// ✗ lichSuResolver mất 4 giây:
// người dùng bấm vào dòng → màn hình CŨ đứng im 4 giây, không dấu hiệu gì
// → họ tưởng máy treo và bấm tiếp nhiều lần

// Và dữ liệu không tự làm mới:
// mở màn 30 phút, số tồn kho vẫn là số của lúc mới vào

Chọn thế nào: dữ liệu nhỏ, bắt buộc phải có (chi tiết bản ghi, danh mục) → resolver. Dữ liệu lớn hoặc có thể tải dần (danh sách, biểu đồ, tab phụ) → cứ vào màn trước, hiện khung xương rồi tải sau — người dùng cảm thấy nhanh hơn nhiều.

Từ điển

Thuật ngữ đã dùng

Thuật ngữNghĩa tiếng Việt
resolverBộ giải dữ liệu — lấy dữ liệu trước khi vào route.
route dataDữ liệu gắn kèm route, đọc qua ActivatedRoute.
withComponentInputBindingTự bơm tham số route vào input của component.
skeletonKhung xương — giao diện giả trong lúc chờ dữ liệu.
NavigationStart/EndSự kiện router báo bắt đầu/kết thúc điều hướng.
