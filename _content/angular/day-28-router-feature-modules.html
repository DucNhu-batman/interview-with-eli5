Là gì

Mỗi tính năng tự giữ bảng route của mình

Ứng dụng lớn không dồn tất cả route vào một file. Mỗi feature (tính năng) có routes.ts riêng, route gốc chỉ trỏ tới. Route con được vẽ vào <router-outlet> nằm trong component cha — nhờ đó dựng được layout có menu/tab giữ nguyên khi đổi màn con.

// features/kho/routes.ts
export const KHO_ROUTES: Routes = [
  {
    path: '',
    component: KhoLayoutComponent,          // chứa router-outlet con
    providers: [KhoStore],                  // service sống theo nhánh route này
    children: [
      { path: '', component: DsKhoComponent },
      { path: ':id', component: ChiTietKhoComponent },
      { path: ':id/sua', component: SuaKhoComponent },
    ],
  },
];

Điểm hay nhất là providers ở cấp route: service khai ở đây được tạo khi vào nhánh và huỷ khi rời đi. Đây là cách sạch nhất để giữ state dùng chung cho vài màn hình mà không làm bẩn phạm vi toàn cục.

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Mỗi nhóm làm một feature mà không đụng file của nhau — ít xung đột khi merge.
  • Layout chung không bị vẽ lại khi chuyển giữa các màn con.
  • State đúng phạm vi, tự dọn khi rời khu vực.
  • Là bước chuẩn bị cho lazy loading ở bài sau — mỗi feature một gói riêng.

Ví dụ mặt lợi

{ path: 'kho', component: KhoLayout, providers: [KhoStore], children: [...] }
// Chuyển giữa /kho, /kho/12, /kho/12/sua: menu và tab KHÔNG bị vẽ lại,
// KhoStore giữ nguyên bộ lọc; rời hẳn khỏi /kho thì store tự huỷ.

−Mặt hại

  • Đường dẫn bị chia nhỏ nhiều nơi, phải ghép trong đầu mới ra URL đầy đủ.
  • Lồng quá sâu làm việc gỡ lỗi điều hướng rất mệt.
  • Nhầm cấp provider tạo ra nhiều bản service không mong muốn.
  • Route rỗng (path: '') lồng nhau là nguồn nhầm lẫn kinh điển về pathMatch.

Ví dụ mặt hại

{ path: '', component: KhoLayout, children: [
  { path: '', component: DsKho },          // thiếu pathMatch: 'full'
  { path: ':id', component: ChiTietKho },
]}
// ✗ /kho/abc khớp cả hai kiểu tuỳ thứ tự → có lúc vào nhầm màn danh sách,
// gỡ lỗi rất mất thời gian vì không có thông báo gì

canDeactivate: [unsavedChangesGuard]   // ✗ khai lại trong routes.ts của feature
// → guard chạy hai lần, người dùng bị hỏi hai lần liên tiếp

Lưu ý riêng của dự án: route feature ở đây được gắn guard chống mất dữ liệu ở cấp gốc (withUnsavedChangesGuard trong main-router.ts). Đừng tự khai canDeactivate trong routes.ts của feature — nó đã được thừa kế sẵn.

Từ điển

Thuật ngữ đã dùng

Thuật ngữNghĩa tiếng Việt
featureTính năng — một khu vực nghiệp vụ của ứng dụng.
child routeRoute con, vẽ vào outlet của component cha.
route-level providerService khai ở cấp route, sống theo nhánh route đó.
pathMatchQuy tắc khớp đường dẫn (full hay prefix).
layout componentComponent khung chứa menu/tab và outlet con.
