Là gì

Cái sàng đặt giữa dòng chảy

Toán tửGiữ lại gì
filter(fn)Chỉ giá trị thoả điều kiện
debounceTime(ms)Giá trị cuối, sau khi im lặng đủ lâu — chống dội phím
throttleTime(ms)Giá trị đầu mỗi khoảng — hợp với sự kiện cuộn
distinctUntilChanged()Bỏ qua nếu trùng giá trị liền trước
take(n) / first()Chỉ n giá trị đầu rồi tự kết thúc
takeUntil(stop$)Nhận cho tới khi luồng stop$ phát — cách dọn dẹp kinh điển
skip(n)Bỏ qua n giá trị đầu (ví dụ giá trị khởi tạo)
 
private destroyRef = inject(DestroyRef);

this.form.controls.tuKhoa.valueChanges.pipe(
  filter((v): v is string => !!v && v.length >= 2),
  debounceTime(300),
  distinctUntilChanged(),
  takeUntilDestroyed(this.destroyRef),   // tự huỷ khi component chết
).subscribe((v) => this.tim(v));

Trong Angular hiện đại, takeUntilDestroyed() thay cho cặp destroy$ = new Subject() + takeUntil(destroy$) + ngOnDestroy. Ít code hơn, không thể quên gọi.

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Giảm mạnh số lần gọi API. Một ô tìm kiếm có debounceTime tiết kiệm hàng chục request mỗi lượt gõ.
  • Tuyên bố rõ ràng. Đọc chuỗi toán tử là biết điều kiện xử lý, không phải lần theo mấy câu if.
  • Tự kết thúc. take, first, takeUntil đóng luồng hộ — hết lo rò rỉ.
  • Type guard trong filter giúp TypeScript loại bỏ null ở các bước sau.

Ví dụ mặt lợi

form.controls.tuKhoa.valueChanges.pipe(
  filter((v): v is string => !!v && v.length >= 2),
  debounceTime(300),
  takeUntilDestroyed(destroyRef),
).subscribe((v) => this.tim(v));
// Gõ "kho hàng A" (10 ký tự): 1 request thay vì 10.

−Mặt hại

  • Đặt sai vị trí là sai kết quả. debounceTime sau switchMap không còn tác dụng chặn request.
  • debounceTime làm giao diện có vẻ chậm nếu đặt quá lớn.
  • takeUntil phải là toán tử cuối cùng, đặt giữa chuỗi có thể không huỷ được phần phía sau.
  • Lọc quá tay khiến người dùng không hiểu vì sao thao tác của mình bị bỏ qua.

Ví dụ mặt hại

api.tim(tk).pipe(
  switchMap((kq) => xuLy(kq)),
  takeUntil(this.destroy$),        // ✗ đặt SAU switchMap
);
// → luồng con bên trong switchMap không bị huỷ, vẫn chạy sau khi rời màn
// Quy tắc: takeUntil luôn là toán tử CUỐI CÙNG.

debounceTime(2000)   // ✗ đặt quá lớn: người dùng gõ xong ngồi chờ 2 giây,
// tưởng ứng dụng bị treo

Thuật ngữ đã dùng

Thuật ngữNghĩa tiếng Việt
filtering operatorToán tử lọc — loại bớt giá trị khỏi luồng.
debounce / throttleChống dội / giới hạn tần suất.
takeUntilNhận cho tới khi một luồng khác phát tín hiệu dừng.
takeUntilDestroyedTự huỷ đăng ký khi component bị huỷ.
DestroyRefĐối tượng đại diện vòng đời huỷ của component.
valueChangesLuồng phát ra mỗi khi giá trị control trong form đổi.
