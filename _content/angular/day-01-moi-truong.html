Là gì

Ba mảnh ghép của một máy trạm Angular

Angular không chạy thẳng trong trình duyệt như một file HTML. Code bạn viết (TypeScript, template, SCSS) phải được build (biên dịch và đóng gói) thành JavaScript thuần trước. Ba công cụ lo việc đó:

  1. Node.js — bộ chạy JavaScript ngoài trình duyệt. Mọi công cụ build đều là chương trình Node.
  2. Package manager (trình quản lý gói: npm, pnpm, yarn) — tải thư viện về node_modules và khoá phiên bản trong package-lock/pnpm-lock.
  3. Angular CLI — bộ lệnh ng để tạo dự án, sinh file, chạy dev server (máy chủ phát triển), build bản phát hành.
node -v            # kiểm tra phiên bản Node
npm i -g @angular/cli
ng new my-app --standalone --style=scss
cd my-app && ng serve -o    # mở http://localhost:4200

Phiên bản không phải chuyện vặt. Mỗi bản Angular chỉ chạy với một khoảng phiên bản Node và TypeScript nhất định. Lệch phiên bản là nguồn của những lỗi build "không thể hiểu nổi". Dự án nên khoá bằng trường engines trong package.json và một file .nvmrc.

Nên biết

Vài lệnh CLI dùng hằng ngày

LệnhLàm gì
ng serveChạy dev server, tự nạp lại khi sửa file
ng generate c tenSinh component kèm file test, đăng ký sẵn
ng buildBuild bản phát hành (tối ưu, rút gọn, chia gói)
ng testChạy unit test (kiểm thử đơn vị)
ng updateNâng phiên bản Angular kèm sửa code tự động (migration)
ng lintSoát code theo quy tắc dự án

Được gì — mất gì

Ưu điểm và nhược điểm của bộ công cụ

+Mặt lợi

  • Cấu hình sẵn, thống nhất. CLI dựng sẵn TypeScript, bundler, test runner, linter — cả đội có cùng một cách làm.
  • Nâng cấp có hỗ trợ. ng update tự sửa phần lớn thay đổi phá vỡ (breaking change) giữa các bản.
  • Sinh code chuẩn. ng generate tạo file đúng quy ước đặt tên, đỡ tranh cãi cấu trúc thư mục.
  • Dev server nhanh. Nạp lại từng phần khi sửa, giữ nguyên trạng thái màn hình.

Ví dụ mặt lợi

# Người mới vào dự án: ba lệnh là chạy được
nvm use            # đọc .nvmrc → đúng phiên bản Node của dự án
pnpm install       # đúng phiên bản thư viện nhờ lock file
pnpm start

# Và nâng cấp có công cụ đi kèm:
ng update @angular/core @angular/cli   # tự sửa phần lớn breaking change

−Mặt hại

  • Nặng. node_modules hàng trăm MB; cài lần đầu tốn thời gian và băng thông.
  • Khó tuỳ biến sâu. Muốn đổi cấu hình bundler phải dùng builder tuỳ chỉnh hoặc "eject" gián tiếp.
  • Rất kén phiên bản. Node/TypeScript/Angular phải khớp nhau; máy mỗi người một bản là hỏng.
  • Che mất bên dưới. Người mới dễ không hiểu chuyện gì xảy ra giữa code và trình duyệt.

Ví dụ mặt hại

# Máy A: Node 20 · Máy B: Node 18
ERROR: The Angular CLI requires a minimum Node.js version of v20.19
# Cùng một commit, máy này build được, máy kia không.

# Và cài lẫn npm với pnpm sinh hai lock file:
package-lock.json + pnpm-lock.yaml
# → mỗi người một cây phụ thuộc khác nhau, lỗi "chỉ xảy ra trên máy tôi"

Thực tế trong dự án: hãy ghi rõ phiên bản Node và package manager vào README, dùng chung một lock file và tuyệt đối không commit node_modules. Người mới join chỉ cần một lệnh cài là chạy được.
