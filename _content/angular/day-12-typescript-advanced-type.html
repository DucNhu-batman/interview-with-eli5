Là gì

Ba phép ghép kiểu

Day 11 dạy cách dán nhãn cho từng biến. Day 12 là ghép các nhãn đó lại với nhau. TypeScript cho ba phép ghép, và chỉ cần nhớ ba chữ tiếng Việt:

  • Union type (kiểu hợp) — dấu | — nghĩa là HOẶC: giá trị là một trong các kiểu liệt kê.
  • Intersection type (kiểu giao) — dấu & — nghĩa là VÀ: giá trị phải có đủ mọi thuộc tính của tất cả các kiểu gộp lại.
  • Conditional type (kiểu có điều kiện) — cú pháp T extends U ? X : Y — nghĩa là TUỲ: kiểu kết quả phụ thuộc kiểu đầu vào.

Bắt đầu từ một hàm có vấn đề. unknown (chưa biết kiểu) chấp nhận mọi giá trị, nên hàm dưới đây nhận cả boolean lẫn mảng — trong khi thân hàm chỉ xử lý được chuỗi và số:

// ✗ quá rộng: cái gì cũng lọt qua cửa
function listen(port: unknown) {
  if (typeof port === 'string') port = parseInt(port, 10);
  server.listen(port);
}

// ✓ union: chỉ chuỗi HOẶC số
function listen(port: string | number) { /* … */ }

listen('3000');   // ok
listen(3000);     // ok
listen(true);     // ✗ Argument of type 'true' is not assignable to 'string | number'
listen();         // ✗ Expected 1 arguments, but got 0

Union dùng được cho cả tham số lẫn giá trị trả về. Muốn tái sử dụng thì đặt cho nó một cái tên bằng type alias (bí danh kiểu):

type StringOrNumber = string | number;

function listen(port: StringOrNumber) { /* … */ }
function getSomething(): StringOrNumber { return 30; }   // hoặc 'ba mươi'

Nhớ đúng hai chữ là hiểu 80% bài này: | đọc là hoặc — kiểu càng nhiều nhánh thì giá trị càng tự do, nhưng bạn dùng được càng ít (chỉ dùng được phần chung). & đọc là và — kiểu càng gộp nhiều thì giá trị càng khó tạo, nhưng bạn dùng được càng nhiều.

Cơ chế

HOẶC nới cửa vào, VÀ nới cửa ra

Bảng tra

toán tử typeof trả về gì

typeof là operator (toán tử) hỏi kiểu của một giá trị lúc chạy. Kết quả luôn là một chuỗi — nên nó là công cụ để thu hẹp một union về đúng một nhánh.

Biểu thứcChuỗi trả về
typeof 'abc''string'
typeof 123'number' — typeof NaN cũng là 'number'
typeof true'boolean'
typeof {}'object'
typeof []'object' — mảng không có nhãn riêng, phải dùng Array.isArray()
typeof null'object' — lỗi lịch sử của JavaScript, không sửa được nữa
typeof undefined'undefined'
typeof (() => {})'function' — typeof String cũng vậy
typeof typeof 1'string' — vì lớp trong đã trả về chuỗi rồi

Phân biệt hai loại lỗi. Union sai chỉ gây compilation error (lỗi lúc biên dịch — lúc tsc dịch TypeScript sang JavaScript). Nhưng tsc vẫn xuất ra file JavaScript, bạn vẫn chạy được, và lúc đó nó nổ thành runtime error (lỗi lúc chạy). Nhãn kiểu bị xoá sạch khi build — đừng trông nó chặn dữ liệu bẩn từ máy chủ.

Dùng thật

Union và Intersection trong một component Angular

Một component (thành phần giao diện) flex-container nhận Input (dữ liệu truyền từ cha xuống) tên flexDirection. Khai kiểu string là mở toang cửa: ai cũng truyền được 'abcxyz' và style hỏng lặng lẽ.

// ✗ string — nhận cả giá trị vô nghĩa
@Input() flexDirection: string = 'row';

// ✓ literal union — chỉ đúng 4 giá trị CSS cho phép
type FlexDirection = 'row' | 'column' | 'row-reverse' | 'column-reverse';

@Component({ selector: 'flex-container', template: '<ng-content></ng-content>' })
export class FlexComponent {
  @Input() flexDirection: FlexDirection = 'row';

  @HostBinding('style.display') get display() { return 'flex'; }
  @HostBinding('style.flex-direction') get direction() { return this.flexDirection; }
}

selector là tên thẻ để gọi component, template là khuôn HTML của nó, còn HostBinding là cách gắn giá trị thẳng lên chính thẻ <flex-container>. Kết quả: khi gõ trong template, editor bật intellisense (gợi ý tự động) đúng bốn lựa chọn, gõ sai là đỏ ngay.

<!-- app.component.html -->
<flex-container>
  <button>Gửi</button>
</flex-container>

<!-- gõ "col…" là editor gợi ý sẵn đủ 4 giá trị -->
<flex-container flexDirection="column">
  <input type="email" />
</flex-container>

Chiều ngược lại là Intersection. Thư viện giao diện nào cũng có một nhúm props (thuộc tính đầu vào của component) dùng chung; thay vì chép lại ở từng component, gộp bằng & — cách này gọi là type composition (soạn kiểu bằng cách ghép):

type StyleProps  = { backgroundColor: string; color: string; margin: string; };
type ButtonProps = { onClick: (e: MouseEvent) => void } & StyleProps;
type TextProps   = { fontSize: string; fontWeight: number } & StyleProps;

// Cùng cách đó cho hàm, nhờ generic (kiểu tổng quát — kiểu có chỗ trống điền lúc dùng)
function merge<T1, T2>(o1: T1, o2: T2): T1 & T2 { return { ...o1, ...o2 }; }

merge({ foo: 'bar' }, { bar: 'foo' });   // { foo: string } & { bar: string }

Kiểu có điều kiện

Một câu if viết ở tầng kiểu

Conditional type có từ TypeScript 2.8. Đọc T extends U ? X : Y là: nếu kiểu T gán được cho kiểu U thì lấy X, không thì lấy Y. Nó biến hệ thống kiểu thành thứ tính toán được, chứ không chỉ khai báo.

type ObjectDictionary<T> = { [key: string]: T };     // support type — kiểu phụ trợ
type ArrayDictionary<T>  = { [key: string]: T[] };

export type Dictionary<T> = T extends [] // T có phải mảng không?
  ? ArrayDictionary<T[number]>                        // đúng → từ điển chứa mảng
  : ObjectDictionary<T>;                              // sai  → từ điển thường

type A = Dictionary<string>;     // { [key: string]: string }
type B = Dictionary<number[]>;   // { [key: string]: number[] }
type C = Dictionary<User>;       // { [key: string]: User }

Dictionary ở đây là true type (kiểu chính, được export ra ngoài dùng), hai cái còn lại là support type (kiểu phụ trợ, chỉ để dựng nên kiểu chính). Tách như vậy để người dùng thư viện chỉ phải nhớ một cái tên.

Bảng tra

Kiểu tiện ích TypeScript cho sẵn

Ghép ba phép trên với mapped type (kiểu ánh xạ — duyệt từng trường của kiểu khác bằng [P in keyof T]), TypeScript dựng sẵn một bộ utility type (kiểu tiện ích) dùng hằng ngày. Không cần thuộc lòng định nghĩa, nhưng nên biết chúng chỉ là vài dòng chứ không phải phép màu:

KiểuLàm gì
Partial<T>Mọi trường thành tuỳ chọn — hợp cho dữ liệu cập nhật một phần
Readonly<T>Cấm gán lại các trường — rất hợp cho state (trạng thái dùng chung)
Pick<T, K>Giữ lại các trường có khoá K
Omit<T, K>Bỏ đi các trường có khoá K — chính là Pick ghép Exclude
Record<K, V>Từ điển: mỗi khoá trong K mang giá trị kiểu V
Exclude<T, U>Bỏ khỏi union T những nhánh gán được cho U
Extract<T, U>Ngược lại: chỉ giữ những nhánh gán được cho U
NonNullable<T>Bỏ null và undefined khỏi T
ReturnType<F>Lấy kiểu giá trị mà hàm F trả về
 
// Định nghĩa thật — toàn conditional + mapped type, không có gì bí ẩn
type Exclude<T, U>   = T extends U ? never : T;
type Extract<T, U>   = T extends U ? T : never;
type NonNullable<T>  = Exclude<T, null | undefined>;
type Readonly<T>     = { readonly [P in keyof T]: T[P] };
type Partial<T>      = { [P in keyof T]?: T[P] };
type Pick<T, K extends keyof T> = { [P in K]: T[P] };
type Record<K extends keyof any, T> = { [P in K]: T };
type ReturnType<T>   = T extends (...args: any[]) => infer R ? R : any;
type Omit<T, K extends keyof T> = Pick<T, Exclude<keyof T, K>>;

// Và cách dùng
type Person = { firstName: string; lastName: string; password: string };

type D = Exclude<'a' | 'b' | 'c', 'c' | 'd'>;   // 'a' | 'b'
type E = Extract<'a' | 'b' | 'c', 'c' | 'd'>;   // 'c'
type F = Pick<Person, 'firstName' | 'lastName'>;   // { firstName: string; lastName: string }
type G = Omit<Person, 'password'>;                // { firstName: string; lastName: string }
type H = Record<'p1' | 'p2', string>;              // { p1: string; p2: string }
type I = ReturnType<() => string>;                // string

Định nghĩa thì trừu tượng, nên đây là một màn hình quản lý nhân viên có thật — mỗi kiểu tiện ích gánh đúng một việc:

// Kiểu gốc: một bản ghi nhân viên máy chủ trả về
interface NhanVien {
  id: number;
  ho: string;
  ten: string;
  email: string;
  matKhau: string;
  trangThai: 'dang_lam' | 'nghi_viec' | 'thu_viec';
  ngayTao: string;
}

// ① Omit — dữ liệu gửi lên khi TẠO MỚI: chưa có id, chưa có ngày tạo
type TaoNhanVien = Omit<NhanVien, 'id' | 'ngayTao'>;
const moi: TaoNhanVien = { ho: 'Nguyễn', ten: 'An', email: 'an@ct.vn',
                           matKhau: '…', trangThai: 'thu_viec' };

// ② Partial + Omit — dữ liệu gửi lên khi SỬA: sửa trường nào gửi trường đó
type SuaNhanVien = Partial<Omit<NhanVien, 'id'>>;
capNhat(7, { email: 'an.moi@ct.vn' });   // ok — không cần gửi đủ 7 trường
capNhat(7, { id: 9 });                     // ✗ 'id' does not exist in type 'SuaNhanVien'

// ③ Pick — một dòng trên bảng danh sách, khỏi kéo cả bản ghi xuống
type DongBang = Pick<NhanVien, 'id' | 'ho' | 'ten' | 'trangThai'>;

// ④ Omit — kiểu trả ra giao diện, cắt hẳn trường nhạy cảm
type NhanVienAnToan = Omit<NhanVien, 'matKhau'>;
nv.matKhau;                                // ✗ Property 'matKhau' does not exist

// ⑤ Record — bảng nhãn tiếng Việt; quên một trạng thái là báo lỗi ngay
type TrangThai = NhanVien['trangThai'];
const NHAN: Record<TrangThai, string> = {
  dang_lam: 'Đang làm', nghi_viec: 'Nghỉ việc', thu_viec: 'Thử việc',
};
NHAN[nv.trangThai];                        // 'Đang làm'

// ⑥ Exclude — bộ lọc không cho chọn người đã nghỉ
type TrangThaiLoc = Exclude<TrangThai, 'nghi_viec'>;   // 'dang_lam' | 'thu_viec'

// ⑦ Extract — chiều ngược lại: chỉ giữ nhánh còn đi làm
type DangDiLam = Extract<TrangThai, 'dang_lam' | 'thu_viec'>;

// ⑧ Readonly — state của màn hình: gán lại là chặn ngay lúc gõ
const state: Readonly<{ ds: DongBang[]; dangTai: boolean }> = { ds: [], dangTai: false };
state.dangTai = true;                    // ✗ Cannot assign to 'dangTai': read-only property

// ⑨ ReturnType — khỏi khai lại cái kiểu mà hàm đã tự biết
function boLocRong() {
  return { tuKhoa: '', trang: 1, trangThai: null as TrangThaiLoc | null };
}
type BoLoc = ReturnType<typeof boLocRong>;
// { tuKhoa: string; trang: number; trangThai: 'dang_lam' | 'thu_viec' | null }

// ⑩ NonNullable — nhánh sau khi người dùng đã chọn xong, chắc chắn khác null
type DaChon = NonNullable<BoLoc['trangThai']>;   // 'dang_lam' | 'thu_viec'

Hai cú pháp mới lọt vào ví dụ trên, đáng để ý:

  • Indexed access type (truy cập kiểu theo khoá) — NhanVien['trangThai'] moi kiểu của một trường ra dùng lại, thay vì chép lại cái union bốn nhánh ở hai chỗ rồi quên sửa một chỗ.
  • typeof ở vị trí kiểu — typeof boLocRong khác hẳn typeof lúc chạy ở bảng trên: đứng trong ngữ cảnh kiểu, nó lấy kiểu của biến/hàm đó chứ không trả về chuỗi. Đây là cặp bài trùng của ReturnType.

infer (suy ra) trong ReturnType là chỗ đáng chú ý: nó nói với TypeScript "chỗ này có một kiểu nào đó, tạm gọi là R, bắt lấy hộ tôi". Đó là cách moi kiểu ra khỏi một kiểu khác mà không phải khai lại bằng tay.

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Kiểu hẹp đúng bằng thực tế. Literal union chặn giá trị vô nghĩa ngay lúc gõ, không đợi tới lúc chạy mới thấy giao diện lệch.
  • Bớt trùng lặp. &, Pick, Omit thay cho việc chép lại một interface gần giống.
  • Kiểu tự bám theo nhau. Sửa kiểu gốc thì mọi kiểu dẫn xuất cập nhật theo, không sót chỗ nào.
  • Editor gợi ý đúng. Union của chuỗi cho ra danh sách chọn, đỡ phải mở tài liệu.

Ví dụ mặt lợi

type CapNhatKho = Partial<Omit<Kho, 'id' | 'ngayTao'>>;
// Thêm một trường vào Kho → CapNhatKho tự có theo

capNhat(1, { id: 5 });   // ✗ báo lỗi ngay: id không được phép sửa

−Mặt hại

  • Dễ quá đà. Conditional lồng bốn năm tầng thì người sau không dám sửa, kể cả chính bạn sau ba tháng.
  • Thông báo lỗi khủng khiếp. Sai một chỗ trong kiểu lồng nhau có thể sinh lỗi dài vài chục dòng.
  • Biên dịch chậm hơn khi lạm dụng conditional và mapped type trong dự án lớn.
  • Vẫn chỉ tồn tại lúc biên dịch. Union không kiểm tra dữ liệu thật từ máy chủ — JSON trả về sai kiểu thì không ai chặn.

Ví dụ mặt hại

type Sau<T> = { [K in keyof T]: T[K] extends object ? Sau<T[K]> : T[K] };
// Type 'Sau<{ a: { b: … } }>' is not assignable to … (40 dòng)

const kho = await api.get<Kho>('/kho/1');
// ✗ máy chủ trả về { id: "1" } — TypeScript tin là number, runtime mới nổ

Sống chung an toàn: dùng union cho tập giá trị hữu hạn, dùng & và Pick/Omit để khỏi chép kiểu, và dừng lại ở đó. Conditional type chỉ đáng viết khi bạn làm thư viện dùng chung; trong code màn hình hằng ngày, một kiểu dài dòng nhưng đọc phát hiểu luôn tốt hơn một kiểu thông minh mà không ai dám đụng. Với dữ liệu từ máy chủ, phải kiểm tra thật lúc chạy chứ đừng tin cái nhãn.
