Là gì

Đường đi từ file tới màn hình

Một ứng dụng Angular chỉ có một trang HTML thật (index.html) — nên gọi là SPA (Single Page Application — ứng dụng một trang). Mọi màn hình sau đó do JavaScript vẽ ra.

  1. index.html chứa một thẻ rỗng, ví dụ <app-root></app-root>.
  2. main.ts là điểm khởi động (entry point), gọi bootstrapApplication(App, appConfig).
  3. Angular tìm thẻ khớp selector (bộ chọn) của component gốc rồi vẽ template của nó vào đó.
  4. Component gốc chứa <router-outlet> — chỗ các màn hình con được thay ra thay vào theo URL.
// main.ts
bootstrapApplication(App, {
  providers: [provideRouter(routes), provideHttpClient()],
});

Bản đồ

File nào để làm gì

Đường dẫnVai trò
src/main.tsĐiểm khởi động, khai báo provider (nhà cung cấp phụ thuộc) toàn cục
src/index.htmlTrang HTML duy nhất, chứa thẻ gốc
src/styles.scssCSS toàn cục
src/app/Toàn bộ code ứng dụng: component, service, route
angular.jsonCấu hình build: đường dẫn, asset, budget, prefix selector
tsconfig.jsonCấu hình TypeScript, alias đường dẫn (@core, @components…)
package.jsonDanh sách thư viện và script chạy lệnh
public/ (assets)Ảnh, font, file tĩnh được sao nguyên vào bản build

Một component gồm bốn phần: lớp TypeScript (logic), template (giao diện), style (CSS riêng, mặc định được cô lập khỏi phần còn lại) và metadata trong @Component (selector, đầu vào, chiến lược phát hiện thay đổi…).

Được gì — mất gì

Ưu điểm và nhược điểm của kiến trúc SPA kiểu Angular

+Mặt lợi

  • Cấu trúc thống nhất. Dự án Angular nào cũng na ná nhau — người mới đọc được ngay.
  • Chuyển màn không tải lại trang. Trải nghiệm mượt, giữ được state (trạng thái) chung.
  • Style cô lập theo component. Không lo CSS của màn này rơi sang màn khác.
  • Tách bạch rõ ràng. Template, logic, style, cấu hình mỗi thứ một chỗ.

Ví dụ mặt lợi

// Style của component không rò ra ngoài — đặt tên thoải mái
// kho.component.scss
.title { color: var(--brand-700); }

// Màn khác cũng có .title mà không đụng nhau:
// Angular tự thêm thuộc tính _ngcontent-abc vào từng phần tử

−Mặt hại

  • Lần tải đầu nặng. Phải tải gói JavaScript rồi mới có gì để nhìn (giảm bớt bằng lazy loading).
  • SEO khó hơn. Nội dung do JS sinh ra; muốn tối ưu tìm kiếm phải dựng thêm SSR (kết xuất phía máy chủ).
  • Nhiều file cho một màn. Ba đến bốn file cho một component nhỏ.
  • Phải học nhiều khái niệm trước khi làm được việc. DI, decorator, module/standalone, RxJS…

Ví dụ mặt hại

// Người dùng mở app lần đầu trên mạng 3G:
main.js  2.4 MB   ← tải hết mới có gì để nhìn
// → màn hình trắng 6–8 giây (chữa bằng lazy loading, Day 29)

// Và bot tìm kiếm chỉ thấy:
<app-root></app-root>   // rỗng, vì nội dung do JS vẽ ra

Thuật ngữ đã dùng

Thuật ngữNghĩa tiếng Việt
SPAỨng dụng một trang — chỉ tải HTML một lần, sau đó JS vẽ tiếp.
bootstrapKhởi động ứng dụng, gắn component gốc vào trang.
selectorBộ chọn — tên thẻ dùng để đặt component vào template.
templateKhuôn giao diện HTML của component.
metadataThông tin mô tả khai trong decorator @Component.
router-outletÔ trống nơi Angular đặt component ứng với URL hiện tại.
providerNhà cung cấp — khai báo cách tạo ra một phụ thuộc.
SSRServer-side rendering — kết xuất HTML sẵn ở máy chủ.
alias đường dẫnBí danh import ngắn gọn thay cho đường dẫn tương đối dài.
