Là gì

Đồ trong túi và chìa khoá kho

Hình dung mỗi biến là một cái túi nhỏ.

Với primitive type (kiểu nguyên thuỷ), món đồ nhỏ gọn nên nằm gọn trong túi. Đưa túi cho người khác là đưa một bản sao của món đồ — họ sửa gì cũng không đụng tới của bạn.

Với reference type (kiểu tham chiếu), món đồ quá lớn nên được cất ở kho; trong túi chỉ có tấm chìa khoá tới kho đó. Đưa túi cho ai là đưa cho họ bản sao của chìa khoá — vẫn mở đúng cái kho ấy. Họ dọn đồ trong kho thì bạn nhìn thấy ngay.

Bảy kiểu nguyên thuỷ: string, number, boolean, null, undefined, symbol, bigint. Tất cả những thứ còn lại — object, array, function, Date, Map, Set… — đều là kiểu tham chiếu.

Cơ chế

Trong túi có gì

let a = 5, b = a;  b++;
console.log(a, b);            // 5 6   — độc lập

let x = { ten: 'An' }, y = x;  y.ten = 'Bình';
console.log(x.ten);           // 'Bình' — cùng một kho

console.log({} === {});       // false — hai kho khác nhau, dù ruột giống hệt
console.log('a' === 'a');     // true  — so sánh theo giá trị

Hệ quả thực tế

Ba điều luôn làm người mới ngã

  1. const không làm object bất biến. Nó chỉ khoá cái túi, cấm bạn đổi chìa khoá; đồ trong kho vẫn sửa thoải mái: const o = {}; o.a = 1; hoàn toàn hợp lệ.
  2. Shallow copy (sao chép nông) chỉ chép một tầng. {...obj} hay Object.assign tạo kho mới cho tầng ngoài, nhưng các object con bên trong vẫn dùng chung chìa khoá cũ.
  3. So sánh object bằng === là so địa chỉ, không so nội dung. Muốn so nội dung phải tự viết hoặc so chuỗi JSON (chậm và có bẫy về thứ tự khoá).
const goc  = { ten: 'An', dc: { tp: 'Hà Nội' } };

const nong = { ...goc };            // shallow copy
nong.dc.tp = 'Huế';
console.log(goc.dc.tp);              // 'Huế'  ← vẫn dính nhau!

const sau = structuredClone(goc);   // deep copy chuẩn, có sẵn trong trình duyệt hiện đại
sau.dc.tp = 'Đà Nẵng';
console.log(goc.dc.tp);              // 'Huế'  ← đã tách hẳn

Được gì — mất gì

Ưu điểm và nhược điểm của mỗi loại

+Primitive — lợi

  • An toàn tuyệt đối. Truyền đi đâu cũng không sợ bị sửa trộm.
  • So sánh rẻ và đúng trực giác. === so đúng cái bạn nghĩ.
  • Bất biến (immutable). Không có thao tác nào sửa được một chuỗi hay một số tại chỗ.
  • Nhẹ. Không cần cấp phát vùng nhớ động, không tạo rác cho bộ thu gom.

Ví dụ mặt lợi

let soDu = 1000;
function tru(x) { x -= 500; return x; }
tru(soDu);
console.log(soDu);        // 1000 — không ai sửa trộm được

−Primitive — hại

  • Copy nhiều thì tốn. Truyền một chuỗi rất dài qua nhiều lớp hàm là chép đi chép lại (engine có tối ưu, nhưng về mặt ngữ nghĩa vẫn là bản sao).
  • Không mang được state. Muốn nhiều nơi cùng thấy một thay đổi thì phải bọc vào object.
  • Vài bẫy riêng: NaN !== NaN, typeof null === 'object', số thực 0.1 + 0.2 !== 0.3.

Ví dụ mặt hại

console.log(0.1 + 0.2);          // 0.30000000000000004
console.log(NaN === NaN);        // false
console.log(typeof null);        // 'object' — lỗi lịch sử của JS

+Reference — lợi

  • Truyền rẻ. Đưa một mảng 10.000 phần tử qua hàm chỉ tốn bằng đưa một địa chỉ.
  • Chia sẻ state. Nhiều nơi cùng nhìn một dữ liệu — nền tảng của mọi kho state (store) và service.
  • Cấu trúc phong phú. Lồng nhau, tự tham chiếu, gắn hành vi (method) vào dữ liệu.

Ví dụ mặt lợi

const ds = [...Array(100000).keys()];
xuLy(ds);                 // truyền 100.000 phần tử chỉ tốn bằng một địa chỉ

// Và nhiều nơi cùng nhìn một dữ liệu:
const gioHang = [];
themSanPham(gioHang, sp);  // màn hình khác thấy ngay, không cần đồng bộ

−Reference — hại

  • Tác dụng phụ khó lần. Một hàm ở tận đâu sửa dữ liệu của bạn mà không báo.
  • Copy dễ hớ. Người ta tưởng đã copy, thật ra vẫn dùng chung — bug kinh điển của mảng cấu hình dùng lại.
  • So sánh không như mong đợi. Hai object "giống hệt" vẫn !==; đây cũng là lý do OnPush trong Angular không nhận ra thay đổi khi bạn sửa tại chỗ.
  • Rò rỉ bộ nhớ. Còn một chìa khoá là cả kho không được thu hồi.

Ví dụ mặt hại

const MAC_DINH = { boLoc: { trang: 1 } };

function moMan() {
  const cauHinh = { ...MAC_DINH };   // tưởng là bản sao
  cauHinh.boLoc.trang = 5;           // ✗ sửa luôn hằng gốc
}
moMan(); moMan();
console.log(MAC_DINH.boLoc.trang);   // 5 — mọi màn sau đều mở ở trang 5

Nguyên tắc vàng: coi dữ liệu là bất biến — thay vì sửa tại chỗ, hãy tạo bản mới ({...cu, ten: 'mới'}, [...ds, phanTuMoi]). Vừa tránh tác dụng phụ, vừa giúp Angular/React phát hiện thay đổi bằng phép so sánh địa chỉ rẻ tiền.

Từ điển

Thuật ngữ đã dùng

Thuật ngữNghĩa tiếng Việt
primitive typeKiểu nguyên thuỷ — giá trị đơn, lưu trực tiếp trong biến.
reference typeKiểu tham chiếu — biến chỉ giữ địa chỉ tới vùng nhớ chứa dữ liệu.
heapVùng nhớ động, nơi các object thực sự nằm.
stackNgăn xếp — vùng nhớ nhanh, giữ biến cục bộ và địa chỉ.
immutableBất biến — không thể sửa tại chỗ, muốn đổi phải tạo bản mới.
shallow copySao chép nông — chỉ chép một tầng ngoài cùng.
deep copySao chép sâu — chép toàn bộ các tầng lồng nhau.
structuredCloneHàm có sẵn của trình duyệt để deep copy đúng chuẩn.
side effectTác dụng phụ — hàm thay đổi thứ nằm ngoài chính nó.
OnPushChiến lược phát hiện thay đổi của Angular, dựa trên so sánh tham chiếu.
