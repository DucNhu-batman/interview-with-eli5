Là gì

Chú bồi bàn riêng có túi đồ dự phòng

Bình thường, khi trang web muốn tải một bức ảnh hay gọi dữ liệu, trình duyệt sẽ gửi thẳng request (yêu cầu gửi lên mạng) ra ngoài máy chủ. Nếu mất mạng hoặc máy chủ sập, trình duyệt lập tức đầu hàng và hiện màn hình con khủng long 🦖.

Service Worker (công nhân dịch vụ chạy ngầm) xuất hiện như một chú bồi bàn cá nhân đứng chắn ngay giữa trang web và thế giới Internet:

  1. Đứng chặn ở cửa: Mọi yêu cầu lấy file HTML, CSS, JavaScript hay hình ảnh đều phải đi qua chú bồi bàn trước khi được bay ra ngoài mạng.
  2. Tự quyết định nguồn lấy: Chú bồi bàn có một chiếc tủ riêng tên là Cache Storage (kho lưu trữ bộ nhớ đệm). Nếu trong tủ có sẵn đồ, chú móc ra đưa ngay tại chỗ trong 0 mili-giây mà chẳng cần hỏi máy chủ.
  3. Sống độc lập với trang web: Chú bồi bàn không sống bên trong trang web mà chạy ở một worker thread (luồng xử lý ngầm riêng biệt). Kể cả khi người dùng đã đóng tab web, chú vẫn có thể thức để nhận push notification (thông báo đẩy) hoặc thực hiện background sync (đồng bộ ngầm khi có mạng lại).

Câu chốt cả bài: Service Worker là một network proxy (người trung gian chặn bắt mạng) nằm ngay trong trình duyệt của người dùng, giúp ứng dụng web có thể chạy mượt mà khi offline (mất mạng) và hoạt động bền bỉ như một ứng dụng di động thực thụ.

Cơ chế 2

Vòng đời 3 bước nghiêm ngặt

Khác với file JS thông thường được tải về là chạy ngay, Service Worker phải trải qua một vòng đời (lifecycle) chặt chẽ để bảo đảm không làm hỏng ứng dụng đang mở:

  1. Đăng ký (Registration): Trang web báo cho trình duyệt biết đường dẫn file Service Worker: navigator.serviceWorker.register('/sw.js').
  2. Cài đặt (Installation): Trình duyệt tải file sw.js về và kích hoạt sự kiện install. Đây là lúc Service Worker tải sẵn toàn bộ sườn ứng dụng (HTML, CSS nền tảng) cất vào Cache.
  3. Kích hoạt (Activation): Khi phiên bản Service Worker cũ không còn tab nào dùng nữa, bản mới bước vào trạng thái activate. Đây là lúc dọn dẹp các kho Cache cũ lỗi thời và sẵn sàng kiểm soát mọi yêu cầu mạng.

Được gì — mất gì

Cân nhắc lợi ích và rào cản kỹ thuật

Được gì (Ưu điểm)

  • Chạy offline 100%: Người dùng vẫn mở được app, xem danh sách dữ liệu cũ và đọc bài viết kể cả khi rơi vào vùng mất sóng hoàn toàn.
  • Tốc độ tải trang tức thì: Đọc từ bộ nhớ đệm trên đĩa cứng máy người dùng (0ms chờ kết nối mạng), loại bỏ độ trễ đường truyền.
  • Thông báo đẩy (Push): Nhận thông báo từ máy chủ về máy ngay cả khi người dùng không mở trang web.
  • Đồng bộ nền (Background Sync): Người dùng ấn "Gửi biểu mẫu" lúc mất mạng, trình duyệt ghi nhớ và tự gửi đi ngay khi vừa có sóng.
  • Không nghẽn giao diện: Chạy hoàn toàn trên luồng phụ, tính toán xử lý dữ liệu nặng không làm đơ giật màn hình của người dùng.

Mất gì (Nhược điểm & Cái giá)

  • Bẫy kẹt Cache (Stale Cache): Lập trình viên cập nhật tính năng mới trên máy chủ nhưng người dùng vẫn thấy phiên bản cũ do Service Worker trả về từ Cache lưu sẵn.
  • Không truy cập DOM trực tiếp: Chạy ở luồng riêng nên không thể dùng window, document hay trực tiếp sửa giao diện (phải gửi tin nhắn qua postMessage).
  • Bắt buộc chạy HTTPS: Vì đứng chặn toàn bộ kết nối mạng nên trình duyệt chỉ cho phép chạy trên kênh mã hoá an toàn HTTPS (ngoại trừ localhost khi phát triển).
  • Khó kiểm thử & gỡ lỗi: Cần thao tác xóa Cache, Update on reload hoặc unregister thủ công trong tab Application của công cụ nhà phát triển (DevTools).

Code thực tế: Đăng ký, dọn dẹp Cache và cơ chế cập nhật an toàn

// ==========================================
// FILE 1: sw.js — Kịch bản Service Worker
// ==========================================
const CACHE_VERSION = 'app-v2'; // Đổi tên version khi có code mới
const STATIC_ASSETS = ['/', '/index.html', '/app.js', '/style.css'];

// 1. Cài đặt: Tải trước tài nguyên tĩnh
self.addEventListener('install', event => {
  event.waitUntil(
    caches.open(CACHE_VERSION).then(cache => cache.addAll(STATIC_ASSETS))
  );
});

// 2. Kích hoạt: TỰ ĐỘNG DỌN DẸP toàn bộ Cache phiên bản cũ
self.addEventListener('activate', event => {
  event.waitUntil(
    caches.keys().then(keys => {
      return Promise.all(
        keys.filter(k => k !== CACHE_VERSION).map(k => caches.delete(k))
      );
    }).then(() => self.clients.claim()) // Chiếm quyền kiểm soát ngay lập tức
  );
});

// 3. Lắng nghe lệnh skipWaiting từ giao diện người dùng
self.addEventListener('message', event => {
  if (event.data && event.data.action === 'SKIP_WAITING') {
    self.skipWaiting();
  }
});

// 4. Chặn bắt request: Chiến lược Stale-While-Revalidate (Lấy cache trước, cập nhật ngầm)
self.addEventListener('fetch', event => {
  event.respondWith(
    caches.open(CACHE_VERSION).then(cache => {
      return cache.match(event.request).then(cached => {
        const networked = fetch(event.request).then(res => {
          if (res.ok) cache.put(event.request, res.clone());
          return res;
        }).catch(() => cached);

        return cached || networked;
      });
    })
  );
});

Code thực tế: main.js — Lắng nghe bản mới và nhắc người dùng Reload

// ==========================================
// FILE 2: main.js — Chạy trên giao diện web
// ==========================================
if ('serviceWorker' in navigator) {
  navigator.serviceWorker.register('/sw.js').then(reg => {
    reg.addEventListener('updatefound', () => {
      const newWorker = reg.installing;
      newWorker.addEventListener('statechange', () => {
        // Đã cài xong bản mới và đang đứng đợi (waiting)
        if (newWorker.state === 'installed' && navigator.serviceWorker.controller) {
          showUpdateBanner(() => {
            // Người dùng bấm "Cập nhật" -> Báo Service Worker bỏ qua hàng đợi
            newWorker.postMessage({ action: 'SKIP_WAITING' });
          });
        }
      });
    });
  });

  // Khi Service Worker mới đã kích hoạt -> Tải lại trang
  let refreshing = false;
  navigator.serviceWorker.addEventListener('controllerchange', () => {
    if (!refreshing) {
      refreshing = true;
      window.location.reload();
    }
  });
}

Cách sống chung an toàn: Không bao giờ dùng skipWaiting() một cách âm thầm vô điều kiện ngay lúc cài đặt nếu ứng dụng có nhiều tab đang mở với phiên bản JS cũ không tương thích. Hãy hiện thông báo cập nhật (Toast/Banner) cho người dùng bấm "Có bản cập nhật mới — Tải lại ngay" để kích hoạt skipWaiting và reload đồng bộ.

Nói trong phỏng vấn

Trả lời thế nào cho gọn

Trả lời 30 giây như Senior: Service Worker là một programmable network proxy (bộ uỷ nhiệm mạng lập trình được) chạy trên Web Worker thread riêng biệt, nằm giữa ứng dụng web và mạng. Nó có 3 đặc tính mấu chốt: (1) Không truy cập DOM mà giao tiếp qua postMessage; (2) Vòng đời độc lập gắn với 3 sự kiện chính (install, activate, fetch); và (3) Yêu cầu HTTPS bắt buộc. Service Worker là nền tảng của PWA để giải quyết 3 bài toán: Offline-first với Cache Storage, Push Notifications và Background Sync.

Hay bị hỏi

Service Worker khác Web Worker thông thường chỗ nào?

Web Worker dùng để tính toán nặng tránh nghẽn UI, gắn chặt vào vòng đời của một tab và chết khi đóng tab. Service Worker là bộ proxy chặn bắt toàn bộ traffic mạng của cả origin, sống độc lập với mọi tab (tắt hết tab vẫn nhận Push Notification), và có quyền truy cập trực tiếp vào Cache Storage API.

Câu hỏi bẫy

Vì sao vừa deploy code mới nhưng người dùng F5 vẫn ra bản cũ?

Do cơ chế bảo vệ của Service Worker: Khi có file sw.js mới, nó tải về và cài đặt nhưng ở trạng thái Waiting (chờ đợi), vì vẫn còn tab cũ đang chạy phiên bản SW trước đó. Nó không tự ý nhảy vào chiếm quyền để tránh làm vỡ dữ liệu. Muốn kích hoạt ngay, code phải gọi self.skipWaiting() và clients.claim().

Câu hỏi Senior

Chiến lược Caching nào cho từng loại tài nguyên?

Cache-First (hoặc Cache-Only) cho các tài nguyên tĩnh có mã hash (CSS, JS, Fonts, Ảnh logo). Network-First cho dữ liệu nhạy cảm thường xuyên thay đổi (Số dư ví, giỏ hàng, thông tin thanh toán). Stale-While-Revalidate cho dữ liệu giao diện cần hiển thị tức thì (0ms) nhưng vẫn cập nhật dữ liệu mới ngầm phía sau (Avatar, danh sách bài viết).

Câu hỏi loại ứng viên

Service Worker có đọc được Token trong Cookie hay LocalStorage không?

Không! Service Worker hoàn toàn không có quyền truy cập vào window, document hay localStorage (vì localStorage là đồng bộ, làm nghẽn worker). Nó cũng không đọc được Cookie qua JavaScript (nhất là HttpOnly). Muốn lưu dữ liệu phức tạp trong Service Worker, ta phải dùng IndexedDB hoặc Cache Storage.

Trả lời sai kinh điển: "Service Worker chỉ đơn giản là một thư viện hỗ trợ lưu cache giống như localStorage." Sai hoàn toàn về bản chất! Service Worker là một luồng hệ thống (OS/Browser-level background process) có khả năng lập trình điều phối luồng mạng, chạy độc lập với giao diện, không phải là một API lưu trữ đơn thuần.

Từ điển

Thuật ngữ dùng trong bài

Thuật ngữ Nghĩa tiếng Việt & Giải thích
Service Worker Công nhân dịch vụ chạy ngầm — kịch bản mã nguồn JavaScript chạy trên luồng riêng biệt phía sau trình duyệt.
Network Proxy Bộ uỷ nhiệm mạng — đối tượng trung gian đứng giữa để nhận, lọc và điều phối các yêu cầu kết nối mạng.
Cache Storage Kho lưu trữ bộ nhớ đệm — nơi lưu các cặp yêu cầu / phản hồi mạng (Request/Response) dưới máy người dùng.
skipWaiting() Bỏ qua hàng đợi — hàm ép Service Worker mới kích hoạt ngay lập tức mà không cần chờ đóng hết các tab cũ.
clients.claim() Chiếm quyền kiểm soát — hàm giúp Service Worker vừa kích hoạt nhận quyền điều khiển mọi trang web đang mở ngay tức thì.
Stale-While-Revalidate Trả cache cũ trước, tải mới ngầm sau — chiến lược vừa giúp app tải tức thì 0ms vừa cập nhật dữ liệu nền.
Offline Ngoại tuyến / Mất kết nối — trạng thái thiết bị không có tín hiệu Internet.
Worker Thread Luồng làm việc ngầm — luồng thực thi tách biệt khỏi luồng chính (Main Thread) nơi vẽ giao diện.
Push Notification Thông báo đẩy — tin nhắn thông báo được máy chủ gửi tới thiết bị dù trang web đang đóng.
Background Sync Đồng bộ ngầm — cơ chế trì hoãn hành động và tự động gửi lại khi thiết bị có kết nối mạng ổn định.
DOM (Document Object Model) Mô hình đối tượng tài liệu — cây cấu trúc biểu diễn các thẻ HTML trên giao diện màn hình.
HTTPS Giao thức truyền siêu văn bản an toàn — kết nối mạng có mã hoá chống nghe lén và can thiệp.

Thực hành với Frontend

Giao tiếp SW ↔ Trang Web & Các case FE thực tế

Service Worker không truy cập được window hay document, nhưng hai bên có thể nói chuyện qua postMessage (gửi tin nhắn hai chiều). Đây là nền tảng cho tất cả các tình huống FE dưới đây.

Case 1 — SW báo tiến trình tải về / prefetch cho FE hiển thị

// ── sw.js ─────────────────────────────────────────
self.addEventListener('install', event => {
  event.waitUntil(precacheWithProgress(STATIC_ASSETS));
});

async function precacheWithProgress(urls) {
  const cache = await caches.open(CACHE_VERSION);
  let done = 0;
  for (const url of urls) {
    await cache.add(url);
    done++;
    // Báo tiến trình về cho tất cả tab đang mở
    const clients = await self.clients.matchAll();
    clients.forEach(c => c.postMessage({
      type: 'CACHE_PROGRESS',
      done,
      total: urls.length,
      percent: Math.round(done / urls.length * 100),
    }));
  }
}

// ── main.js (React / Vanilla) ─────────────────────
navigator.serviceWorker.addEventListener('message', e => {
  if (e.data?.type === 'CACHE_PROGRESS') {
    // Cập nhật progress bar trên UI
    setProgress(e.data.percent);   // React state hook
    if (e.data.percent === 100) showToast('App đã sẵn sàng offline!');
  }
});

Case 2 — FE yêu cầu SW xoá cache theo lệnh (nút "Xoá bộ nhớ đệm")

// ── sw.js ─────────────────────────────────────────
self.addEventListener('message', async event => {
  if (event.data?.type === 'CLEAR_CACHE') {
    const keys = await caches.keys();
    await Promise.all(keys.map(k => caches.delete(k)));
    // Báo lại cho FE: đã xoá xong
    event.source?.postMessage({ type: 'CACHE_CLEARED' });
  }
});

// ── settings-page.js ──────────────────────────────
async function handleClearCache() {
  const sw = navigator.serviceWorker.controller;
  if (!sw) { alert('Không có SW đang chạy'); return; }

  // Lắng nghe phản hồi một lần
  const done = new Promise(res =>
    navigator.serviceWorker.addEventListener('message', e => {
      if (e.data?.type === 'CACHE_CLEARED') res();
    }, { once: true })
  );
  sw.postMessage({ type: 'CLEAR_CACHE' });
  await done;
  showToast('Đã xoá bộ nhớ đệm!');
}

Case 3 — FE phát hiện offline/online, SW phục vụ trang fallback

// ── sw.js: trả trang offline.html khi mất mạng ───
self.addEventListener('fetch', event => {
  if (event.request.mode === 'navigate') {
    event.respondWith(
      fetch(event.request).catch(() =>
        caches.match('/offline.html')   // trang đã cache sẵn khi install
      )
    );
    return;
  }
});

// ── app.js: FE lắng nghe trình duyệt thay đổi mạng ─
window.addEventListener('online',  () => setOnline(true));
window.addEventListener('offline', () => setOnline(false));

// React hook tiện dụng
function useOnlineStatus() {
  const [online, setOnline] = useState(navigator.onLine);
  useEffect(() => {
    const on  = () => setOnline(true);
    const off = () => setOnline(false);
    window.addEventListener('online',  on);
    window.addEventListener('offline', off);
    return () => {
      window.removeEventListener('online',  on);
      window.removeEventListener('offline', off);
    };
  }, []);
  return online;
}

Case 4 — Workbox: cách Angular/React PWA tích hợp SW trong thực tế

Trong Angular (@angular/pwa) và Vite (vite-plugin-pwa), Workbox (thư viện SW của Google) sinh file sw.js tự động. FE chỉ cần tích hợp module SwUpdate (Angular) hoặc useRegisterSW (Vite):

// ── Angular: phát hiện bản mới qua SwUpdate ───────
import { SwUpdate } from '@angular/service-worker';

@Component({ /* … */ })
export class AppComponent {
  constructor(updates: SwUpdate) {
    updates.versionUpdates.pipe(
      filter(e => e.type === 'VERSION_READY')
    ).subscribe(() => {
      // Hiện toast: "Có bản mới — Tải lại?"
      if (confirm('Có bản cập nhật mới. Tải lại?'))
        document.location.reload();
    });
  }
}

// ── Vite PWA (React / Vue): hook đơn giản ─────────
import { useRegisterSW } from 'virtual:pwa-register/react';

function App() {
  const { needRefresh, updateServiceWorker } = useRegisterSW();
  return needRefresh ? (
    <div className="update-banner">
      Có bản mới!{' '}
      <button onClick={() => updateServiceWorker(true)}>Tải lại</button>
    </div>
  ) : null;
}

Case 5 — SW tự động đính kèm Authorization header vào mọi API call

// sw.js: đọc token từ IndexedDB, thêm header cho API calls
import { openDB } from 'idb'; // hoặc dùng indexedDB thủ công

self.addEventListener('fetch', event => {
  const url = new URL(event.request.url);
  if (!url.pathname.startsWith('/api/')) return; // chỉ chặn API

  event.respondWith(addAuthHeader(event.request));
});

async function addAuthHeader(req) {
  const db    = await openDB('auth-store', 1);
  const token = await db.get('tokens', 'access');
  if (!token) return fetch(req);   // không có token → thả qua

  const authed = new Request(req, {
    headers: { ...Object.fromEntries(req.headers), Authorization: `Bearer ${token}` },
  });
  return fetch(authed);
}

// ── main.js: lưu token vào IndexedDB khi login ────
async function saveToken(accessToken) {
  const db = await openDB('auth-store', 1, {
    upgrade(db) { db.createObjectStore('tokens'); },
  });
  await db.put('tokens', accessToken, 'access');
}
Tổng kết pattern FE ↔ SW:
  • FE → SW: dùng navigator.serviceWorker.controller.postMessage()
  • SW → FE: dùng self.clients.matchAll().then(cs => cs.forEach(c => c.postMessage()))
  • FE lắng nghe SW: navigator.serviceWorker.addEventListener('message', handler)
  • SW không có localStorage: mọi dữ liệu cần lưu trong SW phải dùng IndexedDB (bất đồng bộ, an toàn với worker thread).
  • Workbox là lựa chọn chuẩn trong Angular PWA và Vite PWA — không cần viết sw.js tay.
