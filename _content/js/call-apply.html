Là gì

Gọi hàm và chỉ định luôn chủ nhân

Bình thường this do cách gọi quyết định. call và apply cho phép bạn giành lấy quyền đó: gọi hàm ngay lập tức, đồng thời nói thẳng “lần này this là đối tượng kia”.

Hai hàm này giống hệt nhau, chỉ khác cách nhận đối số (argument — giá trị truyền vào hàm):

ham.call(chuNhan, a, b, c);    // đối số rời — Comma
ham.apply(chuNhan, [a, b, c]); // đối số gói trong MẢNG — Array

Mẹo nhớ: call = comma (dấu phẩy), apply = array (mảng).

function gioiThieu(chao, dau) {
  console.log(chao + ', tôi là ' + this.ten + dau);
}
const an = { ten: 'An' }, binh = { ten: 'Bình' };

gioiThieu.call(an, 'Chào', '!');      // Chào, tôi là An!
gioiThieu.apply(binh, ['Xin chào', '.']); // Xin chào, tôi là Bình.

Dùng vào việc gì

Bốn tình huống kinh điển

Vẫn dùng

Kiểm tra kiểu chuẩn xác

typeof nói mảng là 'object', còn null cũng là 'object'. Mượn toString gốc thì phân biệt được tất cả.

Object.prototype.toString
  .call([]);      // '[object Array]'
  .call(null);  // '[object Null]'
Đã lỗi thời

Biến array-like thành mảng

arguments hay NodeList giống mảng nhưng thiếu method. Ngày nay dùng Array.from hoặc spread cho dễ đọc.

Array.prototype.slice.call(arguments);
// nay: Array.from(arguments) / [...arguments]
Đã lỗi thời

Trải mảng vào hàm nhiều đối số

Math.max nhận các số rời. apply từng là cách duy nhất; nay spread ... làm cùng việc đó, rõ ràng hơn.

Math.max.apply(null, ds);
// nay: Math.max(...ds)
Code kế thừa

Gọi constructor cha

Trước khi có class và super(), kế thừa được viết bằng cách gọi hàm cha với this của con.

function NhanVien(ten, luong) {
  Nguoi.call(this, ten);
  this.luong = luong;
}

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Tái sử dụng tối đa. Một hàm phục vụ được mọi đối tượng có cùng "hình dạng", không cần kế thừa.
  • Không tạo hàm mới. Khác bind, call/apply không sinh thêm object hàm — nhẹ hơn khi gọi trong vòng lặp.
  • Kiểm soát this tuyệt đối. Rất tiện khi viết hàm tiện ích, thư viện, hoặc khi phải làm việc với API cũ.
  • apply nhận sẵn mảng. Hợp khi số lượng đối số chỉ biết lúc chạy.

Ví dụ mặt lợi

// Phân biệt được mọi kiểu, kể cả những ca typeof bó tay
const kieu = (x) => Object.prototype.toString.call(x).slice(8, -1);
kieu([]);       // 'Array'   (typeof cho 'object')
kieu(null);   // 'Null'    (typeof cho 'object')
kieu(new Date()); // 'Date'

−Mặt hại

  • Khó đọc. Array.prototype.slice.call(x) không nói lên ý định; người đọc phải dịch trong đầu.
  • Mượn method dễ vỡ. Đối tượng đi mượn phải có đúng những thuộc tính mà method gốc trông đợi, nếu không sẽ lỗi ở tận bên trong.
  • apply giới hạn số đối số. Trải một mảng hàng trăm nghìn phần tử có thể ném RangeError: Maximum call stack size exceeded.
  • Không tác dụng với arrow function. Arrow không có this riêng, nên chỉ định this cho nó là vô ích — một cái bẫy im lặng.
  • Khác nhau giữa hai chế độ. Truyền null làm this: strict mode giữ nguyên null, sloppy mode tự đổi thành window.

Ví dụ mặt hại

const ds = new Array(200000).fill(1);
Math.max.apply(null, ds);   // ✗ RangeError: Maximum call stack size exceeded
// chữa: ds.reduce((a, b) => Math.max(a, b))

const chao = () => console.log(this?.ten);
chao.call({ ten: 'An' });      // undefined — arrow không có this riêng,
// call không báo lỗi, chỉ im lặng không có tác dụng

Ngày nay nên thế nào: phần lớn công dụng cũ của apply đã có cú pháp thay thế rõ ràng hơn (..., Array.from, class/super). Hãy giữ call/apply cho đúng việc chúng vẫn giỏi nhất: mượn method và chỉ định this khi làm việc với code cũ.

Thuật ngữNghĩa tiếng Việt
callGọi hàm ngay, đối số rời, tự chỉ định this.
applyNhư call nhưng đối số gói trong một mảng.
