Phần 1

Là gì?

Hãy tưởng tượng bạn có một cuốn sổ địa chỉ. Nếu bạn ghi tên + số điện thoại theo thứ tự thì đó là Array — tìm kiếm phải lật từng trang. Nếu bạn ghi vào bảng tra cứu A–Z thì đó là Object — tra nhanh hơn, nhưng tên phải là chuỗi và có vài ô cố định (chứa cả số điện thoại của chính quyển sổ!). Map giống cuốn sổ tra cứu cải tiến: bất kỳ thứ gì cũng làm khoá được (kể cả một object), và sổ chỉ chứa đúng thứ bạn bỏ vào — không bị "ô thừa" từ prototype. Set là giỏ chứa đồ không cho trùng — bỏ vào cùng một cái hai lần, vẫn chỉ thấy một.

Bản chất:
  • Map — tập cặp khoá → giá trị (key–value), khoá có thể là bất kỳ kiểu dữ liệu nào, duyệt theo thứ tự chèn.
  • Set — tập hợp giá trị duy nhất, không cho phép trùng lặp, duyệt theo thứ tự chèn.

Cơ chế & So sánh

API cơ bản

// ── MAP ──────────────────────────────────
const map = new Map();
map.set('name', 'Alice');   // thêm / ghi đè
map.set({id: 1}, 'user'); // key là object
map.get('name');           // 'Alice'
map.has('name');           // true
map.delete('name');        // xoá O(1)
map.size;                  // số phần tử O(1)

// Khởi tạo từ mảng cặp
const m2 = new Map([['a', 1], ['b', 2]]);

// Duyệt đúng thứ tự chèn
for (const [k, v] of map) { /* … */ }
map.forEach((v, k) => /* … */);

// Chuyển <-> Object
const obj = Object.fromEntries(map);
const m3  = new Map(Object.entries(obj));

// ── SET ──────────────────────────────────
const set = new Set([1, 2, 2, 3]); // {1,2,3}
set.add(4);                        // thêm
set.has(2);                        // true O(1)
set.delete(2);                     // xoá O(1)
set.size;                          // 3

// Loại trùng nhanh gọn nhất
const unique = [...new Set(arr)];

// Phép tập hợp
const union        = new Set([...a, ...b]);
const intersection = new Set([...a].filter(x => b.has(x)));
const difference   = new Set([...a].filter(x => !b.has(x)));

Phần 3

Được gì — Mất gì

✅ Ưu điểm của Map & Set

  • Khoá bất kỳ: Map nhận object, number, boolean, Symbol, thậm chí null làm khoá — Object chỉ nhận string/Symbol. 
    const cache = new Map();
const req = { url: '/api' };
cache.set(req, { data: 42 }); // object làm key!
cache.get(req); // {data:42} ✓
  • Không bị nhiễm prototype: map.has('constructor') luôn trả false nếu chưa set — Object thì 'constructor' in obj === true ngay cả khi chưa gán. 
    const obj = {};
'constructor' in obj; // true — bẫy prototype!

const map = new Map();
map.has('constructor'); // false ✓
  • Đếm nhanh O(1): map.size / set.size trả về tức thì. Object.keys(obj).length phải tạo mảng mới mỗi lần.
  • Tìm / xoá nhanh O(1): set.has(x) nhanh hơn arr.includes(x) (O(n)) khi tập dữ liệu lớn — đặc biệt quan trọng trong vòng lặp lớn. 
    // Kiểm tra 1 triệu ID: Set thắng tuyệt đối
const allowed = new Set(millionIds);
items.filter(x => allowed.has(x.id)); // O(n) tổng ✓
// vs arr.includes() → O(n²) tổng ✗
  • Thứ tự chèn được bảo toàn: Map/Set luôn duyệt đúng thứ tự bạn thêm vào. Object có thể sắp xếp lại khoá số nguyên lên đầu.

⚠️ Nhược điểm / Chi phí

  • Không serialise thẳng JSON: JSON.stringify(new Map()) cho ra {} — phải chuyển tay trước khi gửi API hoặc lưu localStorage. 
    // ✗ Sai — mất toàn bộ data
JSON.stringify(new Map([['a',1]])); // '{}'

// ✓ Đúng — chuyển sang Object trước
JSON.stringify(Object.fromEntries(map));
  • API khác Object thuần: Không dùng được cú pháp obj.key hay destructuring trực tiếp. Phải gọi .get() / .set() — đôi khi verbose hơn.
  • Overhead bộ nhớ với tập nhỏ: Với dưới ~20 phần tử, Object/Array thường ít tốn bộ nhớ hơn Map/Set vì không cần cấu trúc hash nội bộ. 
    // Cấu hình app nhỏ → Object là đủ, không cần Map
const config = { theme: 'dark', lang: 'vi' };
  • Set không lưu key riêng: Khi cần cả key lẫn value có liên kết, phải dùng Map thay Set.
  • Spread ra Array khi cần filter/map: Set không có .map() hay .filter() trực tiếp — phải spread rồi mới dùng. 
    // Set không có .map() trực tiếp
const doubled = [...set].map(x => x * 2);
Quy tắc chọn lựa an toàn:
  • Dùng Object khi cấu trúc cố định, key là string, cần JSON hay destructuring ngay.
  • Dùng Map khi key không phải string, thêm/xoá thường xuyên, cần đếm size nhanh, hoặc cần bảo toàn thứ tự chắc chắn.
  • Dùng Array khi cần thứ tự, cho phép trùng, có index, cần các method như map/filter/reduce.
  • Dùng Set khi cần tập giá trị duy nhất, kiểm tra tồn tại O(1), hoặc làm phép toán tập hợp (union, intersection).
// Pattern hay gặp: dedup + lọc nhanh
const seen = new Set();
const uniqueUsers = users.filter(u => {
  if (seen.has(u.id)) return false;
  seen.add(u.id);
  return true;
});

// Pattern hay gặp: cache request bằng object làm key
const resultCache = new Map();
function fetchWithCache(params) {
  if (resultCache.has(params)) return resultCache.get(params);
  const res = fetch(params);
  resultCache.set(params, res);
  return res;
}

Phần 4

Nói trong phỏng vấn

Trả lời 30 giây — góc nhìn Senior

"Map và Set được thiết kế để bổ sung cho Object và Array, không thay thế. Map lưu cặp key–value với key bất kỳ và độ phức tạp tra cứu O(1), còn Set đảm bảo tập giá trị duy nhất với kiểm tra tồn tại O(1). Tôi chọn Map khi key không phải string hoặc cần thêm/xoá thường xuyên — đặc biệt hữu ích khi làm cache với object làm key. Tôi chọn Set khi cần loại trùng hoặc kiểm tra membership trong vòng lặp lớn — arr.includes() là O(n), set.has() là O(1). Nhược điểm cần nhớ: Map/Set không serialize thẳng ra JSON."

  • Map vs Object khác nhau điểm gì quan trọng nhất?

    Ba điểm chính: (1) Map nhận bất kỳ kiểu dữ liệu làm key, Object chỉ nhận string/Symbol. (2) Map không bị nhiễm prototype — các key kế thừa từ Object.prototype không xuất hiện trong Map. (3) map.size là O(1) trong khi Object.keys(obj).length phải tạo mảng trung gian.

  • Khi nào dùng Set thay Array?

    Khi cần: (1) đảm bảo không có phần tử trùng, (2) kiểm tra tồn tại của phần tử nhiều lần — set.has() là O(1) so với arr.includes() O(n). Điển hình: danh sách ID đã xử lý, danh sách tag duy nhất, blacklist/whitelist. Nếu cần thứ tự có index hoặc cần .map()/.filter() trực tiếp → dùng Array.

  • 🎯 Câu hỏi bẫy: new Set([1, '1']) có mấy phần tử?

    2 phần tử! Set dùng thuật toán so sánh SameValueZero — tương tự ===. Số 1 và chuỗi '1' là khác nhau. Ngoài lệ: NaN === NaN là false nhưng Set chỉ lưu một NaN — đây là trường hợp ngoại lệ của SameValueZero.

  • 🎯 Câu hỏi loại ứng viên: tại sao JSON.stringify(new Map(...)) ra {}?

    Vì Map không phải plain object — JSON.stringify không biết cách xử lý các iterable nội bộ của Map. Cần dùng Object.fromEntries(map) trước rồi mới stringify, hoặc viết custom replacer cho JSON. Đây là nguyên nhân phổ biến gây mất data khi lưu state vào localStorage.

  • WeakMap / WeakSet là gì và khi nào cần?

    WeakMap và WeakSet giữ tham chiếu yếu tới key (WeakMap) hoặc value (WeakSet) — khi không còn tham chiếu nào khác tới object đó, bộ thu gom bộ nhớ tự xoá luôn. Dùng WeakMap để gắn metadata vào DOM node hoặc object mà không lo rò rỉ bộ nhớ. Nhược điểm: không duyệt được, không có .size.

❌ Câu trả lời sai kinh điển:
"Map chỉ khác Object ở chỗ thứ tự key được đảm bảo" — Sai hoàn toàn. Map khác Object ở tối thiểu 4 điểm: loại key, prototype, kích thước O(1), và hiệu năng với nhiều phép thêm/xoá. Thứ tự chỉ là một trong số đó. Còn nói "Set chỉ là Array không cho trùng" mà không đề cập O(1) lookup là bỏ qua lý do quan trọng nhất để dùng Set trong thực tế.

Thực hành Frontend

Dùng Map & Set trong dự án thực tế

Map và Set không chỉ là lý thuyết — chúng xuất hiện hàng ngày trong các bài toán quản lý trạng thái, xử lý dữ liệu danh sách, và tối ưu hiệu năng render trong React/Angular/Vanilla.

Case 1 — React: quản lý dòng được chọn trong bảng dữ liệu lớn

Dùng Array cho danh sách "đã chọn" → mỗi lần toggle phải includes() O(n) và filter() O(n). Đổi sang Set: cả hai đều O(1).

// ✗ Dùng Array — O(n) mỗi thao tác toggle với bảng 10k dòng
const [selected, setSelected] = useState<string[]>([]);
const toggle = (id: string) => {
  setSelected(prev =>
    prev.includes(id) ? prev.filter(x => x !== id) : [...prev, id]
  );
};

// ✓ Dùng Set — O(1) cho cả has() và delete()
const [selected, setSelected] = useState<Set<string>>(new Set());
const toggle = (id: string) => {
  setSelected(prev => {
    const next = new Set(prev);    // clone để React nhận ra thay đổi
    next.has(id) ? next.delete(id) : next.add(id);
    return next;
  });
};
const isSelected = (id: string) => selected.has(id); // O(1) khi render mỗi row

Case 2 — Normalized store: Map thay thế Object để lưu entity theo ID

Normalized store (kho dữ liệu đã chuẩn hoá) — pattern Redux/Zustand/NgRx hay dùng — thay mảng lồng nhau bằng lookup-by-ID. Map làm điều này sạch hơn Object vì không lo prototype và size O(1).

// Zustand store với Map — CRUD O(1) cho entity
interface User { id: string; name: string; role: string; }

const useUserStore = create<{
  users: Map<string, User>;
  add:    (u: User)   => void;
  remove: (id: string) => void;
  update: (u: User)   => void;
}>()(set => ({
  users: new Map(),

  add: u => set(s => ({
    users: new Map(s.users).set(u.id, u),   // O(1)
  })),

  remove: id => set(s => {
    const next = new Map(s.users);
    next.delete(id);                          // O(1)
    return { users: next };
  }),

  update: u => set(s => ({
    users: new Map(s.users).set(u.id, u),   // ghi đè O(1)
  })),
}));

// Lấy user theo ID: O(1)
const user = useUserStore(s => s.users.get(userId));

Case 3 — Angular: Set cho kiểm tra quyền truy cập (Permission Guard)

// auth.service.ts
export class AuthService {
  private permissions = new Set<string>();

  setPermissions(perms: string[]) {
    this.permissions = new Set(perms);
  }

  // O(1) — gọi trong mỗi route guard, không gây lag
  can(action: string): boolean {
    return this.permissions.has(action);
  }
}

// admin.guard.ts
export const adminGuard: CanActivateFn = (route) => {
  const auth = inject(AuthService);
  const required = route.data['permission'];  // ví dụ 'MANAGE_USERS'
  return auth.can(required) || redirect('/403');
};

Case 4 — Memoize (ghi nhớ kết quả) với Map: tránh tính lại dữ liệu nặng

// Tính toán phân tích dữ liệu biểu đồ: đắt tiền nếu gọi lại
const analysisCache = new Map<string, AnalysisResult>();

function analyzeDataset(dataset: Dataset): AnalysisResult {
  const key = `${dataset.id}-${dataset.updatedAt}`;
  if (analysisCache.has(key)) return analysisCache.get(key)!;

  const result = heavyCompute(dataset);   // tốn 200ms
  analysisCache.set(key, result);
  if (analysisCache.size > 50) {
    // LRU đơn giản: xoá entry đầu tiên (cũ nhất)
    analysisCache.delete(analysisCache.keys().next().value);
  }
  return result;
}

// React: useMemo cũng vậy, nhưng Map cache cross-render và cross-component
const result = useMemo(() => analyzeDataset(dataset), [dataset.id, dataset.updatedAt]);

const unread = articles.filter(a => !viewed.has(a.id)); // O(n)

// Whitelist domain cho iframe / CSP kiểm tra

const isSafe = (url: string) =>

Case 6 — Map làm event emitter nhẹ (thay EventEmitter trong môi trường không có Node)

// Mini event bus dùng Map<string, Set<Function>>
const listeners = new Map<string, Set<Function>>();

function on(event: string, fn: Function) {
  if (!listeners.has(event)) listeners.set(event, new Set());
  listeners.get(event)!.add(fn);
}
function off(event: string, fn: Function) {
  listeners.get(event)?.delete(fn);   // Set đảm bảo không trùng listener
}
function emit(event: string, ...args: unknown[]) {
  listeners.get(event)?.forEach(fn => fn(...args));
}

// Dùng: giao tiếp giữa các module không cần share state
on('user:logout', clearCart);
on('user:logout', resetFilters);
emit('user:logout');   // gọi clearCart + resetFilters
Khi nào Map/Set thực sự tạo ra khác biệt trong FE:
  • Bảng dữ liệu lớn (>500 dòng): Dùng Set cho selected-rows — loại bỏ O(n²) trong vòng lặp render.
  • Normalized store: Map thay Object khi cần thêm/xoá entity thường xuyên và cần đếm size O(1).
  • Permission / Feature flag: Set.has() O(1) — không bao giờ dùng Array.includes() cho danh sách quyền.
  • Cache kết quả tính toán nặng cross-component: Map bền hơn useMemo (sống ngoài React lifecycle).
  • Event bus / pub-sub nhỏ: Map<event, Set<handler>> — Set tự loại handler trùng, Map tra cứu O(1).
