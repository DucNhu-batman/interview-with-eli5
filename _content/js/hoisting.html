Là gì

JavaScript đọc code hai lượt

Trước khi chạy một dòng nào, JavaScript quét trước cả khối code để đăng ký tên — mọi biến và hàm được khai báo trong đó đều được ghi vào sổ. Xong lượt quét, nó mới chạy từ trên xuống.

Hiệu ứng nhìn từ bên ngoài giống như các khai báo bị “kéo lên đầu”, nên người ta gọi là hoisting (nâng khai báo lên đầu phạm vi). Thực tế không có dòng code nào bị di chuyển cả — chỉ là cái tên đã có mặt trong sổ trước khi tới lượt chạy.

Chỉ khai báo được nâng, giá trị thì không. Đây là câu tóm gọn cả bài: cái tên có sẵn từ đầu, còn giá trị chỉ xuất hiện đúng dòng bạn gán.

TDZ (Temporal Dead Zone — vùng chết tạm thời) là quãng từ đầu khối tới dòng khai báo let/const. Trong quãng đó cái tên đã tồn tại nhưng bị khoá: chạm vào là lỗi ngay. Đây là tính năng cố ý, không phải bug — nó biến một lỗi âm thầm thành một lỗi ồn ào.

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Viết theo lối kể chuyện. Đặt logic chính lên đầu file, các hàm phụ trợ xuống dưới — vẫn chạy đúng.
  • Đệ quy tương hỗ. Hàm A gọi B, B gọi lại A, không cần lo hàm nào định nghĩa trước.
  • TDZ bắt lỗi sớm. Với let/const, hoisting biến việc dùng biến quá sớm thành lỗi rõ ràng thay vì undefined trôi nổi.
  • Giải thích được nhiều bug cũ. Hiểu hoisting là đọc được code JavaScript đời cũ mà không hoang mang.

Ví dụ mặt lợi

// Logic chính đọc trước, chi tiết để dưới — vẫn chạy đúng
const hoaDon = tinhTong(gioHang);
console.log(dinhDang(hoaDon));

function tinhTong(ds) { return ds.reduce((a, x) => a + x.gia, 0); }
function dinhDang(n) { return n.toLocaleString('vi-VN') + ' đ'; }

−Mặt hại

  • undefined im lặng. Với var, lỗi không nổ ngay mà lan xuống dưới rồi mới vỡ ở chỗ khác — cực khó lần.
  • Khuyến khích code lộn xộn. "Chạy được là được" khiến thứ tự khai báo bị buông lỏng.
  • Ảo giác về vị trí. Nhiều người tin rằng code thực sự bị di chuyển lên đầu — hiểu sai bản chất dẫn tới suy luận sai.
  • Nhân đôi luật. Bốn cách khai báo hoisting bốn kiểu; phải nhớ bảng trên mới đọc code nhanh được.
  • Trong khối if, hàm khai báo hành xử khác nhau giữa strict mode và sloppy mode, giữa các trình duyệt cũ.

Ví dụ mặt hại

var daDangNhap = true;

function kiemTra() {
  if (!daDangNhap) {            // ✗ đọc biến CỤC BỘ, đang là undefined
    return 'chặn';               // → luôn chặn, kể cả người đã đăng nhập
  }
  var daDangNhap = false;      // khai báo bị nâng lên đầu hàm
}
kiemTra();                     // 'chặn' — không có lỗi nào được báo

Cách sống chung an toàn: luôn khai báo trước khi dùng, bỏ hẳn var, và bật quy tắc no-use-before-define trong ESLint. Làm được ba điều đó thì hoisting gần như không còn cắn bạn nữa — nhưng vẫn phải hiểu để đọc code người khác.

Thuật ngữNghĩa tiếng Việt

TDZTemporal Dead Zone — vùng chết tạm thời: tên đã có nhưng chưa được phép dùng.

TypeErrorLỗi kiểu — dùng một giá trị theo cách nó không hỗ trợ (gọi thứ không phải hàm).
