Day 38 — Dynamic Component

Tạo component bằng code lúc chạy, không khai sẵn trong template — nền tảng của mọi hệ thống dialog, toast và màn hình cấu hình được.

Là gì

Khi không biết trước sẽ vẽ cái gì

Bình thường template quyết định component nào được vẽ. Nhưng có lúc thứ cần vẽ chỉ biết lúc chạy: một dialog do service mở, một widget do cấu hình từ máy chủ, một bước wizard tuỳ loại hồ sơ. Khi đó dùng ViewContainerRef.createComponent().

private vcr = inject(ViewContainerRef);

mo(loai: 'them' | 'sua') {
  this.vcr.clear();
  const ref = this.vcr.createComponent(loai === 'them' ? FormThem : FormSua);
  ref.setInput('id', this.id());
  ref.instance.dong.subscribe(() => ref.destroy());   // phải tự huỷ
}

Trong dự án này bạn hiếm khi gọi API đó trực tiếp: IamDialogService đã bọc sẵn (và tự đóng dialog khi đổi route qua closeDialogOnNavigation). Hiểu cơ chế bên dưới để biết vì sao dialog nằm ngoài cây route và vì sao nó không tự chết khi chuyển màn.

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Giao diện lắp ghép theo dữ liệu: máy chủ trả cấu hình, ứng dụng dựng đúng widget tương ứng.
  • Dialog/toast dùng chung mở được từ bất kỳ đâu, không cần khai thẻ trong template từng màn.
  • Chỉ tải khi cần: kết hợp import() để không đưa component nặng vào gói chính.
  • Tách bạch: nơi gọi chỉ cần biết "mở form sửa", không cần biết form đó trông thế nào.

Ví dụ mặt lợi

// Widget do cấu hình quyết định, thêm loại mới không phải sửa template
const BANG = { bieuDo: BieuDoWidget, bang: BangWidget, the: TheWidget };
for (const w of cauHinh.widgets) {
  const ref = vcr.createComponent(BANG[w.loai]);
  ref.setInput('props', w.props);
}

−Mặt hại

  • Phải tự dọn. Quên destroy() là component sống mãi ngoài cây view — rò rỉ thật sự.
  • Mất kiểm tra kiểu trong template. Truyền sai tên input chỉ biết khi chạy.
  • Không nằm trong cây route nên đổi route không tự đóng — nguồn của lỗi "popup còn treo trên màn mới".
  • Khó đọc, khó lần. Tìm trong template không ra component nào đang hiện.

Ví dụ mặt hại

const ref = vcr.createComponent(FormSua);
// … không ai gọi ref.destroy()
// → subscription bên trong FormSua chạy tiếp sau khi rời màn

ref.setInput('idKho', id);   // input thật tên là 'id'
// → không lỗi biên dịch, chỉ là dữ liệu không bao giờ tới
