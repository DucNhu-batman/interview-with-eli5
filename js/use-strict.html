"use strict" — chế độ nghiêm ngặt

Một dòng chữ duy nhất ở đầu file đổi luật chơi: những lỗi trước đây bị nuốt im lặng nay nổ ra ngay lập tức.

Là gì

Một dòng, hai bộ luật

JavaScript có hai chế độ chạy. Chế độ mặc định — dân gian gọi là sloppy mode (chế độ dễ dãi) — cố gắng “chữa cháy” cho lập trình viên: gõ sai tên biến thì nó tự tạo biến mới, gán vào thứ không được phép ghi thì nó lặng lẽ bỏ qua. Nghe thì tử tế, nhưng đó chính là cách bug trốn được vào tận môi trường thật.

Strict mode (chế độ nghiêm ngặt), bật bằng chuỗi 'use strict', đảo ngược thái độ đó: sai là báo ngay.

'use strict';        // đầu file — áp cho cả file

function f() {
  'use strict';      // hoặc đầu hàm — chỉ áp cho hàm này
}

Có thể bạn đang dùng nó mà không biết: mọi ES module (file dùng import/export) và mọi thân class luôn luôn chạy ở strict mode. Code Angular, React hay bất kỳ dự án bundler (công cụ đóng gói) hiện đại nào cũng vậy — nên bài này giải thích chính cái luật mà code của bạn đang chạy dưới đó.

Được gì — mất gì

Ưu điểm và nhược điểm

+Mặt lợi

  • Bắt lỗi sớm. Gõ sai tên biến nổ ngay tại dòng gây lỗi, thay vì đẻ ra một biến toàn cục ma và vỡ ở nơi khác.
  • Bảo vệ dữ liệu bất biến. Object.freeze mới thực sự có tác dụng — không còn "ghi hụt" âm thầm.
  • this trung thực. this là undefined khi mất ngữ cảnh giúp lộ ra lỗi, thay vì lặng lẽ ghi rác lên đối tượng toàn cục.
  • Engine tối ưu tốt hơn. Bỏ with và các luật động khiến trình biên dịch dự đoán được nhiều hơn.
  • Dọn đường cho tương lai. Cấm dùng các từ dành riêng (implements, interface, package…) làm tên biến.

Ví dụ mặt lợi

'use strict';
let soLuong = 0;
soLuongg = 5;        // ✗ ReferenceError ngay tại đây

// Không có strict mode: lặng lẽ tạo biến toàn cục "soLuongg",
// soLuong vẫn là 0, và bug lộ ra ở màn hình khác vài ngày sau.

−Mặt hại

  • Code cũ có thể vỡ. Bật strict lên một file legacy đang dựa vào biến toàn cục ngầm là gãy ngay.
  • this = undefined gây lỗi mới. Những chỗ vốn dựa vào this trỏ về window nay ném TypeError.
  • Không tắt lại được. Trong phạm vi đã strict, không có cách nào quay về sloppy.
  • Bẫy khi nối file kiểu cũ. Nối nhiều file thành một bundle: một file mở đầu bằng 'use strict' sẽ áp luật lên toàn bộ những file dán sau nó.
  • Dễ đặt sai chỗ. Câu lệnh phải nằm ở dòng đầu tiên của file/hàm; đặt sau một câu lệnh khác là nó bị coi như chuỗi vô nghĩa và không có tác dụng, mà cũng không báo gì.

Ví dụ mặt hại

// Code cũ dựa vào this = window
function dangKy() { this.ten = 'App'; }
dangKy();            // sloppy: gán window.ten — strict: TypeError

// Bẫy khi nối file kiểu cũ:
// a.js mở đầu bằng 'use strict' → b.js, c.js dán sau cũng bị strict theo,
// dù chúng chưa bao giờ được viết để chạy ở chế độ đó.

Khuyến nghị: với dự án mới, đừng viết 'use strict' bằng tay — hãy dùng ES module (import/export) hoặc TypeScript, khi đó strict mode được bật sẵn cho toàn bộ code. Chỉ thêm dòng đó khi phải viết script cổ điển nhúng thẳng bằng thẻ <script>.
